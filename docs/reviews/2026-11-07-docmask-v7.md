## What the builder does

`scripts/build_doc_sidecar.py`:

* `--domain code|math|wiki_ru|instruct` replays the exact `build_mix4.py`
  record order (same filters, dedup, eval shadow, quota/fill passes) and
  verifies **every record byte-for-byte at the cursor**. It also checks the
  replayed record count and byte total against `mix4/manifest.json`:
  code 138,871 / 690,009,645 B, math 47,986 / 632,508,389 B, wiki_ru 29,943 /
  230,028,784 B, instruct 446,511 / 120,500,114 B — all exact.
* `--source-dir` matches whole `*.txt` shards by head, tail, size and full
  content. The final check is `sum(record lengths) == .bin size`, and an
  off-by-one names the offset it failed at.
* `--refuse --reason ...` writes `<bin>.docs.refused.json`. A flat `.bin` with
  no record token is never guessed at.

## Eval boundary policy

The eval window is a fixed contiguous `eval_bytes` (default 196 608 B) from
`eval_offset` (0), cut by `open_streams` as `batches × batch × (seq_len+1)`
bytes; the scored bytes are `batch × seq_len` per batch. Boundaries do not
change **which** bytes the window picks. They change the objective: the flat
window scores a target that lands on the next document's first byte.

The eval stream now uses the same sidecar policy: if a sidecar sits beside the
eval file, `MaskedByteStream` excludes those cross-document targets and the eval
line prints `eval_docmask=sidecar`; without one it stays flat and prints
`eval_docmask=flat (no sidecar)`. `mix_v7`'s `web_eval.bin` has no recoverable
sidecar (it is one flat 6.29 MB shard), so the long run's eval is the recorded
flat number and says so. A doc-masked run therefore does not silently change
the held-out instrument.

## Long run

`configs/mix_v7_docmask.toml` is `mix_v7` minus the three refused sources, with
each stage's weights renormalized over the remaining nine (same relative shares
inside each stage). 43 690 optimizer steps at `b8 × s1024 × grad_accum 3` is
1.074 GB.

```bash
cd /home/sehaxe/dormouse/port

```

The exact plan must be the `docmask` one: a `doc_masking=true` run on
`configs/mix_v7.toml` is refused at the first of the three sources without a
sidecar. If the owner insists on all 12 sources, the honest options are
(a) leave `doc_masking=false` (the flat stream, comparable to the record), or
(b) re-acquire those three domains with record boundaries emitted at build
time. A heuristic split of `reasoning` on `\n---\n` or of `wiki_en` on blank
lines would cut inside a trace/article and is not written.

## Risk if a BOGUS sidecar is enabled anyway

The old file-seam sidecars cut only at 6.3 MB file starts, so they do not cut
mid-sentence; they make `doc_masking` a near-no-op on those bytes (one excluded
target per 6.3 MB) while the log still claims the arm is on. The genuinely
dangerous BOGUS shape is the opposite: an internal boundary invented from a
section marker (`---` appears 700 times in one reasoning shard) would train
across a cut inside a single trace. Neither is used here.

Named cost even on REAL sources: `instruct` has a 269 B mean, so a 1024-byte
row is ~74% padding and the mask pays selected-position compute for a short
document. `science` (1.33 KB) is the next-most padded; fwedu/code/math/wiki_ru
documents are longer than `seq_len` and pay no padding.
