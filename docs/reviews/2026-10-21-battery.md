# Technology battery — 2026-10-20/21 (owner directive: "протестить все и включить все технологии")

One card, sequential arms, `medium` (141.9M), 2000 steps, 3 seeds, eval window
81 920 B for every seq-512 arm (MSA arms: 2 x 2048 x 20 = 81 920 B, the same
number). Data: the 230 GB mixture (`configs/mix_big.toml`) on the filtered
`corpus_bin_filtered.bin` stream; eval `eval_mix/eval_mix.bin`.
Arm flags are the only difference from the control: `ns_kind=triton`,
`opt_graph=true`, `moe_kernel=triton`, `moe_capacity=0` (dropless),
`engram_ram=true`, `bf16=true`, `tf32=true`, `max_iter=3`.
Verdict rule (AGENTS §1.2): a win must beat the control's own seed spread.

## What the numbers say

1. **attnres is real.** It was the one mechanism carried since 2026-09-30 with
   no A/B ("A/B or delete" debt), and on medium it wins by 0.063 BPB — the
   second-largest measured win after ColRow (−0.0428 on the same polygon class)
   and the largest of this battery. It goes into the next training recipe.
2. **MSA is free at 2k.** It does not pay for itself over 2048 tokens (nothing
   to be sparse about) and it does not hurt; its value is the long-context run,
   where the alternative is quadratic attention. Keep it on, report the tie.
3. **Capacity lives in the expert WIDTH, not in more experts per bit.** Halving
   rank costs 0.027 BPB, quartering it costs 0.136 — so the "compress harder to
   fit more experts" trade is a net loss at this scale. TSCT rank 64 stays.
4. **dspark as a pretraining aux is a tie**, consistent with the 2026-10-18 aux
   A/B. Its value, if any, is speculative decoding, not the base objective.
5. **The ByteFlow medium pair did not run**: with `bf16=false` (the ByteFlow net
   refuses bf16) the MoE Triton grouped GEMM needs 196 KiB of shared memory
   against the 101 KiB ceiling. Fix: run that pair with `moe_kernel=padded` on
   both arms. Queued — it is an architecture decision, not a knob.
