# 2026-11-03 — три вердикта и один дефект

Карта: RTX 5070 Ti 16 GB (sm_120). Все числа сняты на ней, один GPU-процесс за раз.

## 1. Флагман 105M: 1.7292 — стена ёмкости

```
171 000 шагов · 4.20 ГБ токенов · 26 803 Б/с · BPB 1.7292
кривая: 1.7300@130k → 1.7328@164k → 1.7292@170k
последние 41 000 шагов при полном decay: −0.0008 BPB
```

Decay не дал ничего, потому что модель уже стояла на потолке. Мой прогноз 1.63–1.68 неверен;
правильный вывод — **105M исчерпана по ёмкости**, дальше только рост модели.

Для сравнения: mix1 = 1.883 на 4.18 ГБ. Тот же бюджет данных, −0.154 BPB за рецепт.

## 2. soft-MTP: DROP

| плечо | BPB | spread |
|---|---|---|
| ntp (контроль) | **3.5829** | 0.0505 |
| hard_mtp | 3.5988 | 0.0206 |
| hard_mtp + seam | 3.5884 | 0.0414 |
| soft_mtp + seam | **3.6129** | 0.0328 |

Правило, записанное до прогона: soft входит, если лучше hard+seam **и** не хуже контроля на
2 разброса **и** acceptance выше. Первое условие провалено (+0.0245 хуже), поэтому DROP.

Отдельно: seam сам по себе дал −0.0104 — TIE, внутри разброса hard_mtp.

**Непроверенное:** acceptance (спек-декод). Проба была выключена, поэтому вторая половина
заявленного выигрыша статьи не измерена. Если понадобится — отдельный прогон с `probe`.

Механика при этом реализована верно: KL-градиент восстанавливается с точностью
**8.9e-16** на каждой голове при K=1..3 (float64, полный словарь), и тождество требует
per-head seam — без него на голове 0 отклонение 0.79. То есть статья не подтвердилась
не из-за ошибки в реализации.

## 3. Конв-кодек: арифметика верна, но реализация течёт

Замер доли кодека от шага (b8 s1024, 314M-форма):

```
attention  8 Б/патч bf16: encode 8.57 + decode 8.00 = 34.8% шага
conv       8 Б/патч bf16: encode 0.84 + decode 0.91 =  5.4%
conv       4 Б/патч fp32: 1.8%
весь шаг: 47.6 → 32.6 мс (×1.46)
```

Арифметика подтвердилась: 357 120 параметров против 93 909 248, 1.27–1.90% MAC против 453–905%.

**Но:** прогон `byteflow_codec=conv` на 314M дал коллапс BPB

```
eval @200: 3.6532   eval @400: 0.4992   train loss @400: 0.7851
```

и это не обучение, а **утечка**: `encode_chunks` берёт `h = embedding(bytes_)` по всему окну и
патчит **неслучайно-каузальной** свёрткой, поэтому латент патча i построен из байтов самого
патча i, а декодер предсказывает именно их. Attention-кодек этого не делает — у него
энкодер причинный (sliding-window causal + causal convs), поэтому его A/B (3.2427 против
3.6152) правдоподобен.

Класс дефекта тот же, что мы ловили трижды: **механизм, который выглядит выигрышем
(−3 BPB!) и обесценивает любой прогон с ним.** Гейты кодека (10 штук) проверяли контракт,
стоимость и градиенты, но не причинность.

Исправление и гейт «инвариантность к будущему» (изменение bytes[:, q:] не должно менять
logits[:, :q] при любом q) — в работе.

## 4. LR для 314M: 5e-4 подтверждён

| LR | сиды | mean | spread |
|---|---|---|---|
| 3e-4 | 2 | 2.7230 | 0.039 |
| **5e-4** | 2 | **2.6571** | 0.070 |
| 1e-3 | 2 | 2.7497 | 0.130 |

Оба сида 5e-4 лучше обоих сидов 3e-4 — порядок устойчивый, не флуктуация. 1e-3 явно хуже.
Значит muP не нужен: тот же LR работает на 105M и на 314M.

Контроль рецепта на 3 сидах, 314M, 800 шагов: **2.6842 / 2.6180 / 2.6007 → 2.6343 (spread 0.0835)**.

## 5. DDP на PCIe 3.0 x8 — не рычаг

```
314M: градиенты 628 МБ, all-reduce на 2 ранга ≈ 1.26 ГБ / 6.5 ГБ/с = 0.19 с
шаг на одной карте 0.40 с → две карты: 0.20 + 0.19 = 0.39 с = ×1.03
```

Мои прежние оценки «×1.7–1.9 через DDP» были неверны. Вторая карта ценна как
**параллельный лейн** (A/B при живом обучении), а не как ранг. Для 1B ZeRO остаётся
осмысленным: обмен 15–20% при выигрыше ×1.7.

## 6. 1B в 16 ГБ: помещается, но не едет

```
состояние 6.1 ГБ (веса 2 + градиенты 2 + моментум 2 + AdamW 0.1)
b8: 26.1 ГБ ❌   b4: 17.1 ❌   b2: 12.1 ✅   b2+it2+ckpt: 10.3 ✅
```

Память не стена — стена скорость: широкая модель на батче 2 launch-bound, 0.25–0.4 ГБ/сутки,
и 20 ГБ токенов = 50–60 суток. Правильный путь — ZeRO на двух картах (райзер x8→x16).
