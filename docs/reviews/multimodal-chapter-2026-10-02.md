# Мультимодальная глава: разбор research-агента владельца (ECG/DNA/аудио/картинки)

Обновлено 2026-10-02. Источник: разбор репо агентом владельца; 5 бумаг в
`docs/papers/mm-*.pdf` (provenance.tsv). Вердикт агента принят владельцем как
план следующей главы.

## Вердикт агента (принят)

«Не отказываться от dormouse, но сменить цель: с "один byte backbone для
всего" на "проверяем, когда общие веса дают перенос между модальностями"».
LM-результаты пока — база для исследования, не основание масштабировать
архитектуру: 4.997 и 5.545 BPB несравнимы между собой (режимы/окна), n-граммный
барьер измерен другим протоколом, прежние результаты ряда механизмов
отзывались. Сначала надёжный baseline, потом модальности.

## Поправки к ранним идеям (важные)

1. **Непрерывный энкодер ≠ непрерывные данные**: байты/основания ДНК/пиксель-
   коды — дискретные; embedding таблица 256 — тот же механизм, что токен-
   таблица. «Без словаря» — неточно: словарь байтов есть, нет BPE-сегментации.
2. **Энкодеры к одному d_model НЕ учат связывать модальности** — нужны
   совместные примеры (ECG+PPG одного человека за один период) и общая цель.
3. Код-наброски (ECG-патч-пример: зашитые 200 патчей, сплющенные каналы)
   считать набросками, не модулями.

## Архитектура: модульный интерфейс (следующая глава)

- Энкодер модальности → последовательность векторов + маска валидных позиций
- Адаптер → размерность бэкбона
- Бэкбон принимает последовательность + позиционную и модальную информацию
- Отдельные task heads
- **Три варианта сравнения**: отдельные модели / энкодеры+общий бэкбон /
  энкодеры+бэкбон с частными модальными ветвями
- **Мультимодальные eval'ы**: перенос между модальностями, поиск пар,
  прогноз одной по другой, работа при пропущенной модальности,
  устойчивость к рассинхронизации

## Первая пара: ECG + синхронная кардиологическая модальность

ECG+PPG или ECG+PCG с синхронными записями — проверка, учит ли общий бэкбон
общую репрезентацию, а не набор классификаторов. DNA — отдельное направление
(не добавлять «ради мультимодальности»).

## Порядок (последовательность агента)

1. Закрепить baseline и повторяемые метрики на одной задаче (текущая программа:
   metric-gate, fidelity-fix, graphfix, depth A/B с φ)
2. Один модальный энкодер против отдельной модели
3. Общий бэкбон приносит измеримый выигрыш → следующая модальность
4. Патчинг/downsampling сигналов — часть дизайна (память/длина), не позднее
   ускорение
