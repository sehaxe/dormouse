# checks.sh: одна дверь для всех гейтов — и два дефекта, которые доработка вскрыла

**Дата:** дорожка начата 2026-10-01, завершена 2026-10-02 · **Ветка:** `wt/checks-sh`
(`de30cda` черновик → `d4152fa` merge main → `5feae4d` форма → `05c91e1` oracle-путь)

## Что это

`tools/checks.sh` — агрегатор уже существующих гейтов репозитория, ничего нового
не enforcing: lib-тесты трёх крейтов через `build_lock.sh run` (замок берётся на
каждую cargo-команду, по usage самого замка), `RUSTFLAGS="-D warnings" cargo doc
--no-deps` (тоже под замком — он компилирует), `check_doc_refs.py`,
`dead_pub_audit.py`, `oracle_gate.py`, `docs-site npm run check` (SKIP без
`node_modules`). Каждый чек: `PASS|FAIL|SKIP` + своё время, хвост 30 строк лога
при FAIL, финальная сводка, exit 1 при любом FAIL (2 — ошибка usage). Флаги
`--fast` (lib-tests, doc-refs, dead-pub, oracle; остальное — SKIP `--fast`) и
`--only NAME`. Не агрегировано нарочно: `lib_gate.sh` (1401 s холодный, второй
cargo-workspace), `test_targets.py` (vendor-scoped), всё `--features cuda`
(§2.4 — решение человека). `dead_pub_audit.py --summary` из брифа не существует
(флаги `--tsv`/`--top`); шапка это фиксирует, PASS там значит «прошёл», не
«мёртвого pub нет» — аудит всегда exit 0 по своему дизайну.

## Дефект 1 — маскировка doc-refs (найден дорожкой 2026-10-01, исправлен на main)

Гейт doc-refs был зелёным только потому, что бродячий **untracked** `research/`
на этом диске делал названные в документах пути существующими. Исправлено на
main как `a0a1dce`; сюда приехало merge'ем `d4152fa`. Механизм стоит записать,
потому что он воспроизводим: `check_doc_refs.py` сканирует **tracked**-файлы
(`git ls-files`), а существование путей проверяет **по файловой системе**.
Любой untracked-каталог, совпадающий с именем в ссылках, превращает красный
гейт в зелёный. Проверено зондом: untracked-документ с путём-призраком гейт не
двигает (файл не в списке), тот же путь в tracked-файле — `FAIL`, exit 1, хвост
с `file:line -> path`. Апгрейд-путь (не эта дорожка): предупреждать, когда путь
разрешается только через untracked-родителя.

## Дефект 2 — oracle_gate лежал с момента переименования C1

`tools/oracle_gate.py` собирал путь к крейтам из частей:
`os.path.join(ROOT, "vendor", "burn-fused", "crates")` (строки 51 и 61).
Переименование `vendor/burn-fused` → `vendor/dormouse-fused` (C1, 2026-10-01)
его не заметило: гейт падал `FileNotFoundError` на старте с тех пор. Почему
прошли обе сетки: план C1 честно отрапортовал «`git grep vendor/burn-fused` → 0
вне `.bulba/`» — и это правда для **токена пути** (проверено на этой ветке: 0
вне `.bulba`, 11 внутри), а `check_doc_refs.py` смотрит токены `vendor/dormouse-fused/…`
и `vendor/cubecl-fix/…` — `vendor/burn-fused` в PREFIXES вообще нет. Путь,
собранный из частей (`"vendor" / "burn-fused" / "crates"`), не видит ни один
path-lint. Исправлено в `05c91e1` двумя строками. Урок: grep-клейм переименования
стоит дополнять grep'ом по **частям** пути (`grep -rn '"burn-fused"' tools/`).

После починки пути гейт **работает и красный по существу** — 3 нарушения R1
(файлы без строки в ORACLE-TIERS.tsv, все — burn-kda, чужие дорожки, записано и
не чинится):

- `vendor/dormouse-fused/crates/burn-kda/tests/kda_param_grads_cuda.rs` — доказательство
  градиентов KDA (`d8fa449`, дорожка kda-gradflow);
- `vendor/dormouse-fused/crates/burn-kda/tests/kda_rope.rs` — дорожки rope-kda/rope-kda2;
- `vendor/dormouse-fused/crates/burn-kda/tests/oracle/upstream/fla_modules_rotary.py` —
  upstream-пин.

Регистрация строки = объявить, с чем файл сравнивается (R1 ADR-0020) — это
решение владельца файла, не агрегатора.

## Дефект 3 — blast radius doc-warnings шире его шапки

Шапка чека обещает «три doc-carrying крейта» (core, data, cli). Но
`dormouse-cli` зависит от `dormouse-train`, а `cargo doc` **компилирует**
замыкание зависимостей под глобальным `RUSTFLAGS`, так что `-D warnings`
превращает в ошибки и предупреждения `dormouse-train`. Первый же полный запуск
гейта (26.7 мин холодных) упал на 8 таких предупреждений — все существовавшие до
дорожки, `crates/` эта ветка не трогает, main краснеет так же (лог:
`~/logs/docwarn-capture.log`, rc=101):

- `optim.rs:63` — неиспользуемый import `Module`;
- `lib.rs:1118/1119` — `tsct_bef`/`tsct_aft` присваиваются, никогда не читаются;
- `lib.rs:1136/1309/1328` — `nan_reads` присваивается и никогда не читается
  (остаток NaN-фаервола/таймеров, §3.1);
- `offload.rs:171` — `HostNgram::to_bytes` never used;
- `jepa_targets.rs:144` — `len` never used.

Это не поломка гейта, а его
честная зона поражения; шапка дополнена абзацем BLAST RADIUS. Чинить
предупреждения — владельцу `dormouse-train`.
