# Landing report, 2026-09-30 (evening)

The brief for this pass was: seven lanes hold verified commits that are NOT on
main; verify each lane's gate, then cherry-pick them in dependency order.

**That premise is false. All ten commits across the seven lanes are already on
`main`, under different hashes, and `main` is strictly AHEAD of every one of
them.** Cherry-picking any of them would REGRESS main. Nothing was
cherry-picked; this file records the evidence, the gates that were actually
run, and the one real finding.

Method: for each lane commit, `git rev-parse <c>:<file>` against
`git rev-parse main:<file>` for every file the commit touches, then
`git diff main <c> -- <file>` read direction-by-direction. A commit is landed
when every file is either an identical blob or one where main carries strictly
more. All ten are.

## THE FINDING: main does not compile. `9ac0377` broke the default build.

Discovered while running the `oracle-a` gate. `cargo build -p burn-rmsnorm` in
`vendor/dormouse-fused` on `main` (at `3234ecc`) fails with **10 errors**:

```
error: cannot find attribute `cube` in this scope
   --> crates/burn-rmsnorm/src/fused.rs:59:3
error: cannot find attribute `comptime` in this scope
   --> crates/burn-rmsnorm/src/fused.rs:65:7
error[E0425]: cannot find function `sync_cube` in this scope
   --> crates/burn-rmsnorm/src/fused.rs:83:5
error: could not compile `burn-rmsnorm` (lib) due to 10 previous errors
```

**Cause, bisected over main's history of that one file.** `fused.rs` gates every
cuda-only item on `#[cfg(feature = "cuda")]`, but the gate on the `#[cube]`
FUNCTION ITSELF was dropped:

| main commit | `#[cfg(feature = "cuda")]` immediately above `#[cube(launch_unchecked)]`? |
|---|---|
| `d1a76fe` self-contained repo (vendored) | **yes** |
| `5c32103` pre.4 cubecl 0.11 migration | **yes** |
| `81e0e77` fix(muon-plus): rank-correct broadcast | **yes** |
| `9ac0377` test(rmsnorm): a gate for the fused kernel | **NO** |

`9ac0377` moved the `THREADS` const and the `#[comptime] threads` parameter
*above* the `#[cube]` fn and, in doing so, took the `#[cfg]` attribute with them
or dropped it; `lib.rs:149` is an ungated `pub mod fused;`, so the whole file is
compiled at default features where `cubecl` is not a dependency at all
(`Cargo.toml:14` puts `dep:cubecl` behind `cuda`). The result is that
`burn-rmsnorm` does not build without `--features cuda`.

**Blast radius.** `lib_gate.sh`'s first cell is
`cargo test --workspace --exclude burn-fused-benches --exclude cpu-probe
--exclude launch-probe` at default features, so **`tools/lib_gate.sh` is red on
main today**, for a reason that has nothing to do with the three tests the
`libgate` lane reported. That is also why this pass could not run the
`lib_gate.sh` gate on main: it does not reach the tests.

**NOT FIXED HERE, deliberately.** `9ac0377` is `wt/fixverify`'s commit and
`fixverify` is on the do-not-touch list (a live agent owns it). The fix is one
attribute on one function. Reporting it with the exact location is the correct
hand-off; editing another lane's file mid-flight is the collision the brief
exists to prevent. Verified location: the attribute belongs on
`vendor/dormouse-fused/crates/burn-rmsnorm/src/fused.rs`, immediately above
`#[cube(launch_unchecked)] fn rmsnorm_kernel` at line 59, where `d1a76fe` had
it.

**It also falsifies a claim on main.** `9ac0377`'s own message says
"CUDA-only: `tools/lib_gate.sh` runs the ndarray cell and will not build this".
That is true about the *test target* it added (which carries
`required-features = ["cuda"]`) and false about the *library*: `lib_gate.sh`'s
workspace cell builds `burn-rmsnorm` as a dependency of the ndarray cell and
cannot skip it. The gate the commit believed it was outside of is the gate it
broke.

## Summary

**What is now on main that was not: nothing.** Zero commits were cherry-picked,
because all ten were already there and main is strictly ahead of every one.
Landing them would have reverted: the f64 fixture layer that replaced the
f32 `ref_data.bin` transcription, the `binary-tests` cell in `lib_gate.sh`, the
wider `oracle_gate.py` scope (3 crates -> 20), the Engram capacity block in
five presets, and 44-118 lines each of `ORACLE.md` / `ORACLE-TIERS.tsv` /
`gen_oracle_tiers.py`.

**What stayed red and why:**
- `burn-rmsnorm` does not compile at default features (`9ac0377` dropped one
  `#[cfg(feature = "cuda")]`). This makes `tools/lib_gate.sh` red on main and

  `vendor/dormouse-fused/crates/burn-rmsnorm/src/fused.rs` above line 59.

  None of the seven lanes addresses it and none was expected to.
- `oracle_gate.py` reports 1 violation: `fused_kernel_gate.rs` is unregistered.
  Same commit, same file family, same fix.

**What was skipped and why:**
- `tools/lib_gate.sh` on main: unreachable, see above.
- The `gdn2bwd` / `rewrite-fwd` conflict the brief predicted (~1654 insertions
  each in overlapping f64-fixture files): **no conflict existed**, because

- The 11 lanes on the do-not-touch list were not read, run, or modified.

generated from `git cherry` at the moment of landing, not written from the
