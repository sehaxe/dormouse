# Security & supply-chain audit — dormouse engine (2026-11-08)

**Lane:** commercial-release readiness. **Read-only** except for the fixes marked
*applied*. **Machine:** CPU only (the GPU was running a training job); no CUDA
tests. Rust changes were verified with `cargo check -p dormouse-cli --bin serve
--no-default-features --features cpu`.

**Method.** Every candidate was read at its call site; nothing here is a
grep-only finding. Checkpoint files that exist on this box were used to test
compatibility claims (they are the engine's own files, not third-party data).
Commands that produced the dependency numbers are quoted in §4.

## 1. Checkpoint deserialization (finding 1) — detail

`torch.load(..., weights_only=False)` is full pickle. The engine loads checkpoints
from `--init-from`, `--ckpt-name`/`--out-dir`, and script flags. A crafted `.pt`
runs code at load time, before any key/shape check, so "I only read the model
half" is not a mitigation.

**Fixed (applied):**

- `port/src/dormouse/train/sft.py:1166` — SFT `--init-from`
- `port/src/dormouse/post/rl_train.py:456` — RL `--init-from`
- `port/scripts/chat.py:70`
- `port/scripts/route_hist.py:81`
- `port/scripts/bench_topk.py:169`
- `port/scripts/bench_adaptive.py:70`
- `port/scripts/kernel_profile.py:862,866`

Regression test: `port/tests/test_checkpoint_safety.py` — proves (a) a
`save_ckpt` file loads under `weights_only=True` (so the safe loader is not a
compatibility break) and (b) a pickle naming a class is refused by the SFT init
path instead of executed. Green.

**Not applied — `loop.py` was being written by another agent throughout this
audit** (mtime advanced three times while reading). Remaining sites:

- `load_model_half` (`loop.py:687`) — default is still `weights_only=False`
  (`loop.py:714`); the concurrent change adds a `--weights-only` **opt-in** flag
  on `eval` (`cli.py:1411`). Safety must be the default, not a flag the caller
  must remember.
- `load_ckpt` (`loop.py:936`) — resume path.
- `train --init-from` (`loop.py:1659`).
- `port/scripts/eval_by_domain.py:101` — new untracked script from the
  concurrent lane.

**Compatibility evidence (verified, 2026-11-08):** every checkpoint on this box
loads under `weights_only=True`, including the optimizer/controller sections:

```
torch.load(f, weights_only=True) on
  port/checkpoints/depth_curve/curve.pt      OK  ['model','model_quant_rung','opt','step']
  port/checkpoints/real_small/k5000.pt       OK  ['model','model_quant_rung','opt','step']
  checkpoints/csa8k/csa8k.pt                 OK  ['model','model_quant_rung','moe','opt','step']
  port/checkpoints/port.pt                   OK  ['model','model_quant_rung','opt','step']
  a fresh save_ckpt() from the test fixture   OK  ['model','model_quant_rung','moe','opt','step']
```

The resume concern in the concurrent docstring ("a future section may name a
class") is a versioning problem: a future writer can bump `format_version` and
teach the reader, while the unpickler stays safe. The config-snapshot gate is
not authentication — an attacker who supplies the `.pt` also supplies the
`.config.toml`, so "trusted file" is not established by that check.

**Recommendation:** make `weights_only=True` the default for all four remaining
sites (`load_model_half`, `load_ckpt`, `train --init-from`, the new script), and
keep the current `--weights-only` flag only as a no-op/deprecated alias if its
name is already documented. Add a CI grep gate: `weights_only=False` outside
`tests/` is a failure.

## 2. RL verifier sandbox escape (finding 2) — detail

`post/verifiers.py` executes model-generated source by design (the code-reward
verifier). Its defence is a regex screen (`_FORBIDDEN`) plus a child preamble
that sets `sys.modules["socket"/"subprocess"/...]=None` and shadows
`builtins.open`. Both layers are bypassable:

```python
# with SANDBOX_PREAMBLE prepended (verified 2026-11-08, benign probes):
import os
os.open("/etc/hostname", os.O_RDONLY)      # os.open is NOT the shimmed builtins.open
sys.modules.pop("socket", None); import socket      # import succeeds again
sys.modules.pop("subprocess", None); import subprocess  # import succeeds; fork blocked by RLIMIT_NPROC=0
```

`RLIMIT_AS`/`RLIMIT_CPU`/`RLIMIT_NOFILE`/`RLIMIT_NPROC` limit runaway, and fork
is blocked, but read/write outside the workdir and network sockets are not. The
docstring's "process jail" claim overstates the guarantee. Threat actor here is
the model being trained (reward hacking) or a prompt-injected task — not an
anonymous remote attacker — but the blast radius is the trainer's user account
and its keys.

**Recommendation:** run the verifier child under `bwrap`/`unshare` (both present
on this box) or a container: no network, read-only root, no `$HOME`, tmpfs cwd.
Python-level shims cannot hold this boundary. If that is not ready for the
release, the module docstring and the release notes must say "not a security
boundary" rather than "jail".

## 3–4. Network exposure (findings 3–4)

- Rust `serve` (`crates/dormouse-cli/src/bin/serve.rs`): now binds
  `127.0.0.1`; `cargo check` green. Remote serving should be
  `reverse-proxy (TLS + auth) -> 127.0.0.1:port`.
- Python `serve` (`port/src/dormouse/serve.py`) already defaults to
  `127.0.0.1`, but has **no authentication** if `--host` is changed, and
  `_body()` (`serve.py:427-433`) reads `Content-Length` with no cap — a
  multi-GB body is a memory DoS. Recommendation: cap the body (e.g. 1 MiB),
  add `Connection: close`/timeouts, and document that `--host 0.0.0.0` needs a
  fronting proxy.
- Dashboard (`port/scripts/dashboard.py`): now defaults to `127.0.0.1`. The
  process already running on this host still listens on `0.0.0.0:3789`; restart
  it (or firewall 3789) to apply.

## 4. Dependencies — measured

```
$ cargo deny check advisories        # 11 advisories, all listed in finding 5
$ uv lock --check                    # ok, resolved 73 packages
$ uv export … | uvx pip-audit -r … --no-deps --disable-pip
  Found 57 known vulnerabilities in 3 packages (pillow 39, filelock 17, setuptools 1)
```

Notes:
- `torch 2.13.0+cu129` comes from the pytorch index and pip-audit **cannot audit
  it** (not on PyPI under that local version) — manual review needed, and the
  CUDA wheel is the largest unaudited binary in the stack.
- `flash-linear-attention==0.5.2` / `fla-core==0.5.2` are exact-pinned with
  hashes, but they execute third-party Triton/CUDA kernels in-process. Accepted
  supply-chain trust, not a defect.
- Rust: zero git dependencies (`deny.toml` `unknown-git = "deny"`), licenses
  allow-listed, CI runs `cargo-deny` with `--all-features`. The gate will be
  **red** on the next push until the 10 advisories are bumped.
- `uv.lock` is hash-pinned and in sync. The `|| uv sync` fallback was the hole;
  it is removed.

## 5. File system / destructive-operation class

- Checked the incident class directly: `git ls-files -s | awk '$1=="120000"'`
  returns one symlink, relative, resolving to a tracked file inside the repo.
  No tracked symlink over an ignored directory; no submodules.
- Writes are confined to the run dir (`save_ckpt` → `out_dir`), an explicit
  `--json-log` path, the export path, and `data_local/bench`. No `rmtree`,
  no delete-by-glob, no writes outside user-named paths. The only unbounded
  user-named write is `ckpt_name` traversal (finding 9).
- `bench.download` creates parents and writes JSONL under `data_local/`; no
  archive extraction, no `tar`/`zip` path-traversal surface.
- The Rust export format is a custom length-checked + CRC32-checked binary, not
  serde/bincode — no deserialization surface.

## 6. CI permissions / cache

- `pull_request_target`: absent (verified by grep over all workflows).
- `permissions: contents: read` added at the top of `ci.yml` and
  `fused-library.yml`; `docs-site.yml` already scopes `pages: write` +
  `id-token: write` and only runs on push/`workflow_dispatch`.
- Cache writes (`Swatinem/rust-cache`, `setup-node cache: npm`) are keyed by
  lockfiles and branch-scoped; no obvious cross-branch poisoning path. A PR
  cannot write the default branch's cache.
- Still recommended: SHA-pin actions, `persist-credentials: false` on every
  checkout (the read-only token makes this defence-in-depth, not urgent), and a
  `CODEOWNERS` entry for `.github/workflows/**`.
- The actionlint job verifies its own download with SHA256 — good; keep it.

## Top 5 priorities

1. **Flip the four remaining `torch.load(..., weights_only=False)` sites to
   `True`** (`loop.py:714,936,1659`, `eval_by_domain.py:101`) and add the
   no-`weights_only=False`-outside-tests CI grep. This is the only finding with
   a direct "download a model, get RCE" path.
2. **Isolate the RL verifier** (`post/verifiers.py`) with `bwrap`/container
   (no network, no home, read-only root) or stop calling it a jail in the
   release documentation.
3. **Bump the Rust advisories** (tokio unsoundness in the shipped server, the
   zstd/parquet memory-safety chain) and re-run `cargo deny check`; the repo's
   own gate is currently red.
4. **Bump `pillow`, `filelock`, `setuptools`** in `uv.lock` and re-run
   pip-audit; refresh the lock after the concurrent agents land.
5. **Restart the dashboard on loopback** (or firewall 3789) and front any
   `serve` deployment with TLS + auth; the endpoints themselves have none.

## What was NOT covered

- GPU/CUDA code paths and kernels (the card was busy; CPU-only audit). Triton
  kernels from FLA were not executed or reviewed for memory safety.
- `torch` CVEs: the `+cu129` wheel is not on PyPI, so pip-audit skipped it;
  manual review against PyTorch's advisories is needed.
- Full `cargo test` for the Rust crates (only `cargo check` on the changed
  binary); the Rust audit is dependency- and config-level, not a line-by-line
  review of 20 crates.
- Git history / deleted blobs: secret scan covered the working tree, not
  `git log -p` or packed objects.
- Host-wide hardening (sudoers, world-writable files outside the repo, SSH
  config); only `ss -tlnp` and failed units were sampled.
- Content authenticity of the training corpora (only the download mechanism was
  checked, not the bytes).
- Files being created by concurrent agents at report time (e.g.
  `port/scripts/bench_engine.py`, `port/scripts/eval_by_domain.py`); the one
  known unsafe read in the latter is listed above.
