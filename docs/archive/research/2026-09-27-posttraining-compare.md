# Post-training 2026: does Rufus-Air transfer to a 7.5M byte-level model?

Date: 2026-09-27 · Supersedes `2026-09-26-posttraining-compare.md` (that file's §1–2 are still correct; this one goes deeper on §3–5, which is where the answer actually lives).

**Question.** Dormouse is a byte-level LM (vocab 256, raw bytes) at 7.5M params, targeting 100M–1B, that wants to become a universal assistant: coding, math, physics, agentic computer use, browsing. Is Rufus-Air ([arXiv:2609.29421](https://arxiv.org/abs/2609.29421)) really the best post-training recipe, or does something else transfer better — especially to small models?

**Verdict, up front.** Rufus-Air is the best *documented* recipe, and its four load-bearing principles (SFT-as-capability-floor, learnability filtering, reward-reliability ordering, infra-is-the-recipe) are the right things to copy. But **Rufus-Air is not the recipe that transfers to dormouse, and the 8-stage serial shape is the least transferable part of it.** Two independent reasons:

1. It is proven at 106B-A12B with 27.04B SFT training tokens on 512×H200. The smallest end-to-end SFT+RL pipeline published *anywhere* runs at ~124M. Dormouse today is 16× below that, and its 100M–1B target lands exactly in the one band where a recipe has actually been run end to end: [nanochat](https://github.com/karpathy/nanochat).
2. The field moved past it in 2026. INTELLECT-3, MiMo-V2.6 and Nemotron 3 all collapsed serial per-domain RL into **one mixed run + multi-teacher on-policy distillation afterwards**. Rufus-Air itself names multi-teacher OPD as the unexplored alternative (§6) that Nemotron shipped as MOPD and MiMo shipped as MOPD2.

## 1. The six recipes, verified against primary sources

Every row below was read this session from the source named. Sections marked "full text" were read in the HTML; the rest from arXiv abstracts / official cards.

### 1.1 Rufus-Air — Amazon, 2026-09-24 — [arXiv:2609.29421](https://arxiv.org/abs/2609.29421) *(abs + full HTML read)*

- **Base/scale**: GLM-4.5-Air-Base, 106B total / 12B active MoE, architecture and tokenizer treated as fixed. SFT on 512×H200 (64 8-GPU nodes, batch 4096 seqs, AdamW, 3 epochs); RL stages on 8–32 nodes.
- **Stages (serial, 8)**: SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF.
- **SFT data**: 9.01M samples, 44.5B raw tokens, 27.04B loss-bearing tokens across 6 categories from **17 public datasets, zero regenerated by Rufus-Air**, zero new human annotation. Sample-share ≠ token-share (Math + Coding Agent = 18.8% of samples but 49.1% of training tokens). Decontamination removed 4,187 unique samples (chain of 8-gram passes + exhaustive 8-gram + dense Llama-NV-Embed retrieval on math/knowledge).
- **Reward types, stage by stage**:
  - Reasoning RL: binary, deterministic. Math-Verify canonical match (83.5% of prompts, `\boxed{}`, median 5-token gold label), generated Python checkers for puzzles, fuzzy match for science.
  - Coding RL: binary. Parse the **last** fenced ```python block, execute in sandbox, assert-tests or stdin/stdout. Tests sub-sampled to ≤50 with a **SHA-256-seeded** choice so the reward does not drift with sampler randomness. No format penalty needed (fenced-block compliance already 98–100% at iter 0).
  - IF RL: **rubric-based binary, all-rubrics-must-pass**. Code-verifiable rubrics via Python; the rest via teacher LLM judge. Rubrics describe *only necessary conditions* — §3.4 records that attaching ~10 *optional* rubrics per instance induced a pronounced length bias.
  - General Agent: **binary, code-based verification only, no step-level and no LLM-judge reward at all.** AWM tasks, MCP servers with ~35 tools/env, tool schemas registered directly in the system prompt (no discovery step to enforce).
  - Coding Agent: binary `tests/test.sh` against final sandbox state, single `execute_command` tool, Harbor task format.
  - Search Agent: **LLM judge** — the one soft stage, and it runs second-to-last.
  - RLHF: preference reward model, last.
- **Difficulty filtering (§3.2–3.7, and §6 "On learnability filtering")**: before training, drop prompts solved >80% (Coding RL: all 4 of 4 warm-up samples; note Coding RL *keeps* never-solved prompts, the other stages drop them). During training, Reasoning RL over-samples 4× and keeps only groups with mean reward ∈ (0, 0.8] (DAPO); General/Coding Agent drop all-pass and all-fail groups.
- **Core novelty**: not an algorithm. (i) SFT is capability-building, not warm-up — SFT ckpt 3799 alone already beats the official RL-included GLM-4.5-Air release on IFEval +5.3, IFBench +24.2, AIME25 +6.6, AIME26 +3.5, trailing only GPQA −5.7. (ii) Reward reliability sets stage order *by exposure to hacking, not by format* — IF RL uses a rubric judge yet runs early because the target is close to what the policy already does. (iii) The epoch-1 finding: **held-out scores flatten inside epoch 1 while loss keeps stepping down at each epoch boundary; they ship ckpt 3799 from the plateau, not the last checkpoint.** (iv) Infra as recipe: token-in/token-out on-policy multi-turn rollouts, one chat template from SFT through the agent stages, stateful sandboxes, Rollout Routing Replay for the MoE.
- **Two practical controls worth stealing verbatim**: length penalty relative to the **shortest correct rollout in each group** (zero at/below it, linear to a cap), and **tagging infrastructure failures as "aborted" and removing them from the group before computing the group baseline** so sandbox boot failures don't bias advantages.
- **Cost, stated honestly**: sandbox service sized for ~10K concurrent sandboxes ≈ **$10K/month**; one BrowseComp pass (1,266 questions × ~100 tool calls) ≈ 10^5 search+extraction calls ≈ a few hundred dollars at list prices.
- **§6 limits, verbatim**: stage order "is one that worked, not one shown to be optimal"; Coding Agent was trained on the compute available, not to convergence; no single benchmark tracked across all stages; multi-teacher on-policy distillation not explored. (The paper also carries an internal inconsistency it does not fully resolve: the IF RL checkpoint reads GPQA 71.1 in Table 9 and 73.36 in Table 10.)
- **Code**: no dedicated repo. Paper + public data + open-source components (Slime, Megatron, SGLang).

### 1.2 Tülu 3 — AI2, 2024-11 (v5 2025-04) — [arXiv:2411.15124](https://arxiv.org/abs/2411.15124) *(abs read)*

- **Stages (3)**: SFT → DPO → **RLVR** (GSM8K + MATH + IFEval constraint checks, PPO with rule-based rewards). RLVR *last*.
- **Base/scale**: Llama 3.1 8B / 70B / 405B. **Smallest proven: 8B.**
- **Core novelty**: coined **RLVR** as a named method; and the discipline around it — multi-task eval scheme with **development and unseen** splits, standard benchmark implementations, substantial decontamination of open datasets, full release of data + code + infra, and explicitly "analysis and discussion of **training methods that did not reliably improve performance**" (online DPO, rejection sampling).
- **Data findings that held**: scaling unique prompts beats reusing SFT prompts for preference data; on-policy preference pairs beat off-policy.
- **Code**: fully open.

### 1.3 INTELLECT-3 — Prime Intellect, 2025-11-26 — [blog](https://www.primeintellect.ai/blog/intellect-3) *(read)*

- **Stages (2)**: one large SFT stage on GLM-4.5-Air base → **one large-scale mixed RL stage** across Math, Code, Science, Logic, Deep Research, SWE. 512×H200 / 64 nodes / 2 months.
- **Rewards**: all environment rewards rule-based/verifiable. No preference stage at all.
- **Core novelty**: infrastructure-first. `prime-rl` is **async-only** — "async training is simply the only practical way to efficiently scale RL to long-horizon agentic rollouts without incurring bottlenecks based on the slowest rollouts per step." [verifiers](https://github.com/PrimeIntellect-ai/verifiers) + Environments Hub (500+ tasks, pinnable standalone modules) + Prime Sandboxes (bypasses the K8s control plane, direct Rust→pod path, sub-10s startup at mass concurrency, hundreds of isolated sandboxes/node, sandbox provisioning overlapped with first-turn reasoning to hide startup entirely).
- **Honesty**: benchmark scores "generally trend up and do not appear to have reached a plateau" — the released checkpoint is a budget checkpoint, not a converged one.
- **Forward work worth noting**: making the model **manage its own context** (cut, branch, lightweight external memory) so long-horizon behavior is trainable.
- **Code**: all open (prime-rl, verifiers, environments, weights).

### 1.4 MiMo-V2.6 — Xiaomi, ~2026-09 — [HF card](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL) *(read)*

- **Stages**: cold start (incl. **Aligned RL**: cold start *from self-correction* — the model rewrites its own misaligned turns into grounded next steps) → **one mixed RL run** → **MOPD2** multi-teacher on-policy distillation for the hard-to-verify remainder.
- **Base/scale**: 309B total / 15B active sparse MoE, 1M ctx, omni (text/image/video/audio), 5-layer MTP drafter. (The card's sidebar says 311B; the model summary says 309B/15B — a trivial card inconsistency.)
- **Rewards**: "**You Only RL Once**" — coding, general agents, visual, cybersecurity from multiple harnesses in the same batch, "so capabilities reinforce each other and strategies transfer to harnesses never seen in training." Async GRPO, 1,568 prompts × 16 rollouts/step, billions of tokens per update. **Groupwise Agentic Grading**: GRS builds task-specific rubrics offline from *contrasting rollouts* and fuses rubric quality with test outcomes; GAR ranks passing trajectories online and moves advantage toward higher-quality/shorter ones — because "binary pass/fail cannot rank passing solutions." Anti-hacking: "environment hardening, adversarial screening, and verifier cross-checks keep the loop honest against reward hacking."
- **Core novelty**: **scaling the grader as the scarce resource.** When the outcome reward saturates, the reward *signal* is what you scale.
- **Code**: weights + RL dataset open; technical report PDF on HF; **no training-code repo**.

### 1.5 Open-Reasoner-Zero — StepFun/Tsinghua, 2025-03 — [arXiv:2503.24290](https://arxiv.org/abs/2503.24290) *(abs read)*

- **Stages**: **one** — pure RL from the base model, no SFT at all.
- **Base/scale**: Qwen2.5-32B base.
- **Rewards**: straightforward rule-based. Vanilla PPO, GAE(λ=1, γ=1), **no KL regularization** (KL and entropy coefficients zero). Beats DeepSeek-R1-Zero on AIME2024/MATH500/GPQA-Diamond at **1/10 the training steps**. The learned critic devalues repetitive responses, giving more robust advantage estimates.
- **Core novelty**: minimalism as the result — every extra trick (KL, curated SFT floor) shown unnecessary *for the reasoning-RL phenomenon at 32B*.
- **Code**: open.

### 1.6 SimpleRL-Zoo — HKUST, COLM 2025 — [arXiv:2503.18892](https://arxiv.org/abs/2503.18892) *(abs read)*

- **Stages**: **one** — zero RL (rule-based math rewards) from base.
- **Base/scale**: **10 base models, Qwen2.5 0.5B → 32B**, Llama3-8B, Mistral-7B/24B, DeepSeek-Math-7B, Qwen2.5-math-7B. The only one of the six with sub-1B evidence.
- **Core novelty**: mostly **negative results**, and the single most important sentence in this report for dormouse: "Most recent efforts to reproduce zero RL training have primarily focused on the Qwen2.5 model series, which may not be representative as **we find the base models already exhibit strong instruction-following and self-reflection abilities**." Qwen-based reproductions therefore *overstate how general the phenomenon is*. Also: increased response length does not always correlate with the emergence of verification behaviour ("aha moment"); the aha moment was **first observed in non-Qwen small models**, and only with careful **format-reward adjustment and query-difficulty control**.
- **Code**: open (code, models, analysis tools).

### 1.7 Scale ladder of the six

SimpleRL-Zoo **0.5B–32B** · Tülu 3 8B–405B · ORZ 32B · INTELLECT-3 106B · Rufus-Air 106B · MiMo-V2.6 309B. **No byte-level post-training recipe exists at any scale** (arXiv search returns only ByT5-style task fine-tuning and hobby national-model reports).

## 2. The load-bearing invariants, and where each recipe states its own

| Invariant | Rufus-Air | Tülu 3 | INTELLECT-3 | MiMo-V2.6 | ORZ | SimpleRL-Zoo |
|---|---|---|---|---|---|---|
| **Verifiable rewards before judge/model-based** | §2.1 + §6 "On stage order": order tracks *exposure to reward hacking*; reasoning/coding first, RLHF preference last | RLVR is a named final capability stage; preference data on-policy from the model itself | all RL env rewards rule-based/verifiable; no preference stage | GRS/GAR *is* the answer to binary saturation; "verifier cross-checks keep the loop honest" | "straightforward rule-based rewards", no KL | rule-based only |
| **Difficulty filtering to a productive band** | §3.2: correctness filter (teacher must solve) + learnability filter >0.8 drop, zero-success drop; online DAPO r̄∈(0,0.8] at 4× oversample | earliest form: RLVR data confined to verifiable domains | difficulty pools + online filter drops pass-rate-1 | difficulty assessment per problem; GAR ranks *within* group | length/repetition handled by the critic | "controlling query difficulty" is **one of the two** key design strategies |
| **SFT floor is capability, not warm-up** | §1 finding 1 + §3.1: "RL works best when the model already has [parseable formats, breadth, multi-turn]"; SFT alone beats the official RL'd release on 4 of 5 anchors | ~939K-sample curated mix is the base of the pipeline | SFT establishes the prior; RL is the second stage | cold start before RL | **explicit counterexample**: RL works from base, no SFT | **counterexample too**, but only for reasoning-shaped tasks and only with difficulty control |
| **One output format end-to-end** | §4: "chat template handling kept consistent from SFT through the agent stages"; role-aware schema with per-message loss mask, validated | chat-template consistency studied as a variable | tool-call format standardized across environments | multi-harness mixing requires format discipline | n/a (single-turn boxed answers) | **format reward is a tuned knob, base-model dependent** |
| **Aborted/infrastructure samples ≠ reward-0** | §3.6: tag aborted samples, drop them from the group before the baseline | — | async trainer with step-level off-policyness | adversarial screening of the loop | — | — |
| **Publish what didn't work** | §6 "On what the recipe does not establish" | "methods that did not reliably improve performance" | no-plateau honesty; collapse ablations | failure-driven anti-hacking sections | the whole paper is "extra tricks are unnecessary" | the paper *is* negative results |

**The real 2026 disagreement is serial-vs-mixed, and it is unresolved.** Rufus-Air runs 8 serial stages; INTELLECT-3 runs one mixed RL stage; MiMo-V2.6 runs one mixed run and states the transfer rationale explicitly; Nemotron 3 Ultra ([arXiv:2606.15007](https://arxiv.org/abs/2606.15007)) runs SFT → multi-environment RLVR → MOPD; Domyn-Small 10B ([arXiv:2607.20448](https://arxiv.org/abs/2607.20448)) runs GRPO-VR → DPO → a final multi-environment GRPO across five domains including tool calling. **Nobody has shown serial > mixed or vice versa at matched compute.** What *has* converged across four independent orgs is the tail: **mixed RL, then multi-teacher on-policy distillation for whatever the verifiers cannot see.**

## 3. What is actually proven below 1B (the decisive section)

The prior report's answer ("sub-1B evidence is thin but real, all RLVR or SFT-only") is right but understates how much has appeared since. Ranked by how directly it constrains dormouse.

### 3.1 nanochat — the only complete SFT+RL pipeline published at ~124M — [github.com/karpathy/nanochat](https://github.com/karpathy/nanochat) *(README + `scripts/chat_sft.py` + `scripts/chat_rl.py` + `runs/speedrun.sh` read in full)*

This is the closest thing to dormouse's future self that exists. `d12` is GPT-1-sized (~124M) and is Karpathy's recommended iteration scale; `d24` is GPT-2-grade (val_bpb 0.718, CORE 0.2690, beating GPT-2's 0.256525 in 1.80 h on 8×H100). **The whole ladder — pretrain → SFT → RL — is three scripts.**

**SFT stage** (`chat_sft.py`), mixture in full:
```
SmolTalk(split="train")            460K rows × 1   # general conversation
MMLU(auxiliary_train)              100K rows × 3   # multiple-choice format
GSM8K(main, train)                  8K rows × 4   # "teaches Math and Tool Use"
```
The critical structural fact: **tool use is not a separate agentic dataset. It is carried inside the math task** — GSM8K solutions execute Python via `nanochat/execution.py` (sandboxed, with tests), and 8K rows × 4 epochs of it is what teaches the model to emit and consume tool calls. The ratio is ~460K chat : 32K math-with-tool-use.

SFT hyperparameters (all inherited from the pretrain checkpoint, all explicit defaults): `max_seq_len` 2048, `total_batch_size` 524288 tokens, `init-lr-frac` **0.8**, `warmup_ratio` **0.0**, `warmdown_ratio` **0.5**, `final_lr_frac` 0.0, `weight_decay` **0.0**, Muon momentum ramped 0.85→0.95 over 300 iters, Adam for embedding/unembedding (0.3 / 0.004), Muon for matrices (0.02). Optimizer momentum buffers are warm-started from pretraining but LRs are restored afterwards, because pretraining's warmdown leaves LRs near zero. Loss mask: **assistant completions only** — `mask=0` for user prompts, BOS, special tokens, **and tool outputs**; packing is BOS-aligned best-fit, and rows are *padded, never cropped*, so no token is ever silently discarded.

**RL stage** (`chat_rl.py`), which is the whole recipe in ~250 lines. Its own docstring is the most useful small-scale guidance published anywhere:

> "I put GRPO in quotes because we actually end up with something a lot simpler and more similar to just REINFORCE: 1) Delete trust region, so there is no KL regularization to a reference model 2) We are on policy, so there's no need for PPO ratio+clip. 3) We use DAPO style normalization that is token-level, not sequence-level. 4) Instead of z-score normalization (r − mu)/sigma, only use (r − mu) as the advantage."

Concretely: GSM8K train only, **1 epoch**, reward = `train_task.reward(conversation, generated_text)` (a programmatic check on the decoded string); `examples_per_step` 16 total across ranks, `num_samples` **16** per example, `max_new_tokens` **256**, temperature 1.0, top-k 50; `init-lr-frac` **0.05** (RL runs at 5% of the SFT/base LR); LR is a **simple rampdown to zero, no warmup**; Muon `matrix_lr` 0.02, Adam `embedding_lr` 0.2 / `unembedding_lr` 0.004, `weight_decay` 0.0. Advantages are `rewards - rewards.mean()` per group; the PG objective is `sum(logp * advantage) / num_valid_tokens`. **Prompt tokens and forced tool-use tokens get `mask=0`, so they carry no loss** — identical to the SFT masking rule.

Two things to note carefully:
- **The chat template, the loss mask, and the tool protocol are all established in SFT and never touched by RL.** The RL stage only changes the policy's arithmetic accuracy.
- README caveat: "float16 training automatically enables a `GradScaler` … **SFT supports this too but RL currently does not**." A grad-scaler gap on the RL path is exactly the underflow hazard that matters at dormouse's LR and batch size.

Evaluation is also cheap and small-model-shaped: **ChatCORE** = mean centered accuracy over ARC-Easy / ARC-Challenge / MMLU / GSM8K / HumanEval, normalized against the 0.25 / 0.0 random baselines, reported as an aggregate plus a categorical-only variant.

### 3.2 The rest of the sub-1B and ~1B evidence

| Source | Scale | What it establishes |
|---|---|---|
| **SimpleRL-Zoo** [2503.18892](https://arxiv.org/abs/2503.18892) | Qwen2.5-0.5B | Zero RL from base *does* work at 0.5B — but only with tuned format reward + query-difficulty control. And the warning: Qwen bases already self-reflect, so this is not evidence a non-Qwen base will reproduce it. |
| **Reward granularity in RLVR** [2607.02869](https://arxiv.org/abs/2607.02869) | Qwen2.5-0.5B, GRPO, GSM8K | **Process-only 63.73% vs outcome-only 53.75%** — a ~10pp gap. Process models produce structurally consistent, arithmetically grounded traces; outcome models produce concise but derivation-error-prone chains. Hybrid weights track process weight, except λ=0.1 (low process / high outcome) which *underperforms* pure outcome — conflicting signals. |
| **MBPP code RLVR** [2605.30478](https://arxiv.org/abs/2605.30478) | Qwen3-0.6B, Llama3.2-1B (LoRA) | RLVR improves pass@1 by up to **13pp** with a combined unit-test + linter reward, GRPO vs GSPO. **Hazard**: static-analysis-only shaping biases the policy toward *shorter* completions that reduce lint errors **without reliably improving functional correctness**. Combined rewards fix the degeneration. |
| **L20-Edu-135M** [2606.22189](https://arxiv.org/abs/2606.22189) | **134.5M, one L20** | **The negative result that matters most.** Direct GRPO-style RLVR on GSM8K **decreased** exact-match accuracy **1.82% → 1.59%** (192-token completions) and **1.21%** (320-token). The authors are careful: "these single-run results identify a concrete failure mode rather than establishing a general lower bound." |
| **Plasticity vs Rigidity** [2601.06677](https://arxiv.org/abs/2601.06677) | ≤1.5B, one A40, <24 h, RLVR + LoRA | LoRA **r=8 consistently fails**; **r=256** unlocks plasticity → 40.0% pass@1 on AIME 24 (+11.1 abs), pass@16 70.0%. But: **heavily math-aligned models suffered performance collapse** — "noisy, low-budget RL updates can act as destructive interference for models already residing near a task-specific optimum." Instruction-tuned models instead spent the budget elongating CoT to maximize reward. |
| **Learning from Less** [2604.18381](https://arxiv.org/abs/2604.18381) | SLM, low-data RLVR | On procedural tasks: models trained on lower-complexity tasks generalize to higher complexity; **mixed-complexity data gives up to 5× the sample efficiency** of easy-only data. |
| **Selective Left-Shift** [2607.07748](https://arxiv.org/abs/2607.07748) | SLM, code (Qwen3-8B for the main runs) | States the trilemma plainly: SFT is bottlenecked by data scarcity, test-time scaling too expensive, and **"Reinforcement Learning from scratch yields near zero advantages."** Their pipeline: offline synthesis with iterative compiler+test feedback → SFT on verified data → RLVR on execution-grounded I/O tests, *"where the SFT prior constrains exploration away from syntax errors."* **Ablations confirm both the SFT phase and execution-grounded rewards are necessary for stable training.** |
| **SOD (step-wise on-policy distillation)** [2605.07725](https://arxiv.org/abs/2605.07725) | **0.6B student** | **26.13% on AIME 2025** via tool-integrated reasoning. Names the OPD failure mode: erroneous tool calls cascade across subsequent steps, progressively amplifying student-teacher divergence until the teacher's token supervision is useless. Step-wise divergence reweighting fixes it; up to +20.86% over the second-best baseline. |
| **ATOD** [2606.27814](https://arxiv.org/abs/2606.27814) | small SLM agents, ALFWorld / WebShop / Search-QA | The clearest small-scale verdict on **GRPO for agentic work**: ATOD beats OPD by **4.16** points and **GRPO by 23.62** points, and beats its own teacher by 2.16. The stated reason is structural: RL optimizes reward but "sparse and delayed feedback makes early-stage learning much less efficient than OPD." |
| **Prefix-GRPO** [2607.19395](https://arxiv.org/abs/2607.19395) | small agents, TextCraft / BabyAI / ALFWorld | "Direct distillation from strong teacher trajectories often turns rich multi-turn behavior into one-shot imitation targets," which is inefficient in long-horizon environments. Replay teacher prefixes to recover valid intermediate states, then let the student continue online; ablations show replay alone is insufficient without explicit prefix-token optimization. |
| **DR-Venus** [2604.19859](https://arxiv.org/abs/2604.19859) | **4B**, ~10K open-data trajectories | Agentic SFT (strict cleaning + resampling of long-horizon trajectories) → agentic RL on IGPO with **turn-level rewards based on information gain + format-aware regularization**, explicitly "to make RL effective for small agents." Beats prior agentic models under 9B. |
| **SWE-Protégé** [2602.22124](https://arxiv.org/abs/2602.22124) | Qwen2.5-Coder-7B-Instruct | States the SLM failure mode on SWE tasks bluntly: "pervasive action looping and low resolution rates." Fix = learn to selectively consult an expert, recognize stalled states, and follow through; SFT on expert-augmented trajectories + agentic RL that **explicitly penalizes degenerate looping and unproductive expert collaboration** → 42.4% SWE-bench Verified (+25.4) with ~4 expert calls/task and 11% of tokens. |
| **TinyLLM** [2511.22138](https://arxiv.org/abs/2511.22138) | TinyAgent, TinyLlama, Qwen, xLAM, BFCL | 1–3B models **significantly outperform** <1B models on function calling; best 65.74% overall and 55.62% multi-turn with a *hybrid* SFT+PEFT+RL+DPO recipe. Direct evidence that **<1B tool-calling is a weak regime**. |
| **MENTOR** [2510.18383](https://arxiv.org/abs/2510.18383) | SLM, executable-tool benchmarks | Names the small-model dilemma exactly: "sparse outcome rewards provide insufficient guidance, whereas strict trajectory matching imposes overly restrictive constraints." On-policy distillation with a flexible, process-aware reward beats both SFT and strict RL OOD. |
| **Replacing thinking with tool usage** [2507.05065](https://arxiv.org/abs/2507.05065) | up to **3B** (DeepMind) | Instead of spending test compute on natural-language CoT, format those tokens as a **multi-turn interaction trace with a stateful tool** in a custom DSL. Yields **faster sampling and a denser reward signal** — "allowing even models of size up to 3B parameters to learn how to proficiently expend additional compute." |
| **GRPO for SLM function calling** [2509.04518](https://arxiv.org/abs/2509.04518) | SLM | A well-shaped reward — structured-JSON validity + correct tool selection + precise parameter use — makes GRPO work for function calling at small scale. |
| **Bittensor Agent Arenas** [2606.10064](https://arxiv.org/abs/2606.10064) | Qwen3-4B, ShoppingBench | "Small-model agentic post-training is bottlenecked less by the algorithm than by the trajectory substrate it consumes." Frontier-synthesised data collapses the long tail; production logs are contaminated by shortcut behaviour. Also: SFT leaves a big pass@8→pass@1 gap (53.3% vs 34.8%), and a per-step teacher-grounded **Dr. GRPO** reward converts that headroom into process improvement. |
| **GRLO** [2605.15464](https://arxiv.org/abs/2605.15464) | **Qwen3-4B-Base** | The cheap path: RLHF learned *from scratch* in open-ended environments, **5K prompts, 22.7 GPU-hours**, 24.1 → 63.1 average, ~46× less data and ~68× less compute than an in-domain RLVR baseline — competitive with Qwen's released post-trained models. Then a *subsequent* in-domain RLVR stage "brings only selective gains." |
| **Terminus-4B** [2605.03195](https://arxiv.org/abs/2605.03195) | Qwen3-4B post-trained | A 4B subagent (SFT + RL with rubric-based LLM-judge reward) for terminal execution cuts the main agent's token usage ~30% at no performance cost, and beats Claude Sonnet / Opus / GPT-5.3-Codex on that subtask. |
| **Nanbeige4.1-3B** [2602.13367](https://arxiv.org/abs/2602.13367) | 3B | A 3B generalist doing reasoning + code + agentic together: **complexity-aware code rewards** (correctness *and* efficiency), and turn-level supervision in deep search giving **reliable 600-tool-call turns**. |
| **ChemCRAFT** [2601.17687](https://arxiv.org/abs/2601.17687) | SLM + sandbox | "Scientific reasoning is not solely an emergent ability of model scale, but a learnable policy of tool orchestration." SMILES-GRPO for a dense chemical reward. |
| **SmolTulu** [2412.08347](https://arxiv.org/abs/2412.08347) | ablations at **135M**, model at 1.7B | Tulu 3 pipeline (SFT → DPO, **no RLVR**) at SmolLM2-1.7B → SOTA sub-2B on IFEval 67.7 (+11) and GSM8K 51.6 (+3.4); ARC variant 57.1 (+5.4). The methodologically important finding: **LR-to-batch-size ratio is strongly task-dependent** — reasoning tasks (ARC, GSM8K) want higher ratios, pattern-recognition tasks (HellaSwag, IFEval) want lower. Recipe *hyperparameters* do not transfer down-scale even when the stage structure does. |
| **ufakzeka-1** [2609.25081](https://arxiv.org/abs/2609.25081) | **151M** (182M w/ embeddings), ~$286, byte-level tokenizer at 1.77 tok/word | Three-stage pretrain, post-training on open + generated data, **no RL**. Findings that transfer: (a) a safety gate "fixed" with data written from its own questions read **64/64** while the honest figure was **34/64**; (b) **training-seed variance was as large as the spread across every recipe tried, so single-seed comparisons at this scale are uninformative**; (c) data rounds repaired only what was absent — identity tracking over long context and multi-turn arithmetic did not move under any data change, "which we read as limits of the model size rather than gaps in the data." |
| **SmolLM3** [HF blog](https://huggingface.co/blog/smollm3) *(read)* | 3B | The fully-open small-model recipe, and it **deliberately skips RL**: "Most existing approaches involve complex reinforcement learning processes and proprietary datasets." Shape: reasoning **mid-training** (35B-token dataset, 4 epochs ≈ 140B tokens, ChatML, wrapped packing) → **SFT 1.8B tokens** (1B non-reasoning + 0.8B reasoning, 4 epochs, BFD packing, loss masked on user turns *and tool results*) → **APO** (off-policy DPO; Tulu 3 preference mixture for non-reasoning, synthetic pairs for reasoning with Qwen3-32B as *chosen* and Qwen3-0.6B as *rejected*) → **model merge** 0.9 APO-soup / 0.1 mid-training checkpoint, which recovered the RULER score APO had destroyed. Chat template separates **XML Tools** from **Python Tools** sections, and `/think` vs `/no_think` are system-prompt flags with the response pre-filled with empty think blocks in no-think mode. |
| **Nemotron 3 Ultra** [2606.15007](https://arxiv.org/abs/2606.15007) | 550B/55B | SFT → RL → **MOPD** (multi-teacher on-policy distillation), multi-environment RLVR, NVFP4, reasoning budget control. Independent confirmation of the SFT→mixed-RL→OPD tail. |
| **Nemotron-3-Nano-CC** [2609.02849](https://arxiv.org/abs/2609.02849) | 30B-A3B | 22K curated problems, SFT + RL for competitive programming: IOI 2025 **130 → 291** post-training, 468 with GenCorrect test-time compute. |
| **Salesforce Koa** [2609.15066](https://arxiv.org/abs/2609.15066) | Nemotron-3-Super-120B | Spec-driven GRPO: expand workflow specs into persona-conditioned multi-turn tasks with task-resolution rewards grounded in successful tool use. Gains clearest on multi-turn tool use. |
| **Puro-2B** [2608.27370](https://arxiv.org/abs/2608.27370) | 1.5B | Cheap pretraining recipe ($6.9K for the best model) whose unusual value here is an **end-to-end case study of how pretraining data curricula shape post-training outcomes** — only possible with the full pipeline. |

### 3.3 The sub-1B verdict

- **RLVR that measurably works at 0.5–0.6B exists** (SimpleRL-Zoo 0.5B, SOD 0.6B at 26% AIME25, the MBPP 0.6B/1B +13pp, nanochat d12). The difference from failure cases is always the same three things: a **pre-existing parseable format** (from SFT), a **dense or process-level reward**, and a **difficulty band**.
- **The one clean negative at ~135M** is L20-Edu-135M's plain GRPO on GSM8K (1.82% → 1.59%). Read it as a failure-mode demonstration, not a law — but it is the closest published analogue to "7.5M model, sparse outcome reward, no format floor."
- **Nobody has published a post-training ablation at 100M–7.5M.** nanochat's d12 (~124M) is the smallest thing with a complete pipeline, and dormouse is 16× below it.
- **Nobody has published a byte-level post-training result at any scale.** The nearest byte-level data point is ufakzeka-1's byte-level *tokenizer* at 151M, with SFT-only post-training.

## 4. What transfers to a byte-level model targeting coding + agentic work

### 4.1 What is tokenizer-agnostic (most of the reward layer)

Every verifiable reward in every recipe operates on **decoded text**: Math-Verify canonicalization on a `\boxed{}` payload, a Python `exec` of the last fenced block against assert tests, a regex over the response for IF constraints, a JSON schema check for tool calls. Dormouse's output is a byte string; `String::from_utf8` and the rest of the stack is unchanged. **Nothing in RLVR requires a 150K vocab.** The ladder transfers; the *token economics* do not.

### 4.2 The three byte-level specifics that actually bite

1. **Chat formatting is a pure data-format choice, so it must be designed like a wire protocol, not like a tokenizer.** nanochat's `<|assistant_start|>` / `<|assistant_end|>` and SmolLM3's ChatML are BPE *special tokens* — free, unambiguous, and impossible to confuse with user text. A byte model has no such escape. Pick role delimiters that cannot occur in the corpus (control bytes 0x00–0x08 are near-certainly absent from UTF-8 text) and make the loss mask a function of those bytes. SmolLM3's finding that **XML-tool and Python-tool schemas want separate template sections** is a free win here: a byte model has no tokenizer to disambiguate them, so section boundaries must be explicit byte markers.
2. **A tool-calling format is bytes, and the sandbox is the same sandbox.** The tool protocol costs dormouse nothing extra in representation; the cost is *context length*. A tool call + observation round trip is pure bytes, and dormouse has a very short context budget for trajectories.
3. **Byte sequences are ~3–4× longer per content token** than a BPE model. Any long-CoT-style RL is therefore *even less* viable than the parameter count alone suggests. This is the strongest argument against the Reasoning-RL stage as dormouse's first RL target, and the strongest argument for the DeepMind tool-trace formulation ([2507.05065](https://arxiv.org/abs/2507.05065)): **replace thinking tokens with tool-interaction turns**, which are shorter, verifiable, and reward-dense per byte.

### 4.3 The minimal viable version, and which recipe's stage structure transfers

**Which structure transfers: nanochat's, not Rufus-Air's.** The reason is not taste, it is the reward-density argument plus the two independent measurements that GRPO underperforms OPD by 23.6 points on multi-turn agentic tasks at small scale (ATOD) and that sparse outcome rewards give a small model insufficient guidance while strict trajectory matching over-constrains it (MENTOR). Rufus-Air's own ordering principle — order stages by exposure to reward hacking — applied honestly to a 7.5M model says: the *only* stage worth running is the one whose reward is hardest to game and cheapest to compute, and that is unit-test execution on short single-turn coding problems.

Minimal viable, with sizes anchored to the nanochat d12 mixture (the only published sub-200M SFT recipe) and scaled to dormouse's byte counts:

- **Stage 0 — SFT floor, one format, tool use carried inside math.** ~10K–100K conversations. Ratio from nanochat: ~14:1 general chat to math-with-tool-execution. 2–4 epochs. Loss on assistant bytes only; zero loss on user, system, and tool-observation bytes. **Ship the checkpoint where held-out evals flatten, not where loss flattens** (Rufus-Air §3.1, measured on 27B tokens: evals flat within epoch 1). Budget: 10–100M bytes. This stage exists to buy exactly three things Rufus-Air names: parseable formats, breadth, and enough successes for sparse rewards to reinforce.
- **Stage 1 — execution-grounded RLVR on short single-turn code + math.** Reward: binary unit tests in a local sandbox (dormouse needs none of INTELLECT-3's sub-10s container fleet — nanochat's in-process `execution.py` is enough). Group size 8–16, temp 1.0, ~256 new bytes/tokens, **RL LR at 5% of the SFT LR** (nanochat's `init-lr-frac` 0.05), no KL, no trust region, advantage = r − μ, rampdown to zero. **Process-level reward where possible** — at 0.5B that was worth ~10pp over outcome-only ([2607.02869](https://arxiv.org/abs/2607.02869)). **Pre-filter prompts to the productive band**: keep observed pass rate in (0, ~0.8], the band every recipe independently converged on.
- **Stage 2 — on-policy distillation, not GRPO, for anything multi-turn.** This is where ATOD, SOD, MENTOR, Prefix-GRPO and Nemotron's MOPD all point, and it is the one place dormouse should copy the 2026 frontier (MOPD2) rather than Rufus-Air. SFT on the teacher's trajectories in dormouse's own byte format, then anneal toward the reward.
- **Do not build yet**: judge/rubric rewards, sandbox-scaled agent RL, RLHF, browsing. All three are the most gameable (Rufus-Air's own ordering principle) *and* the most expensive in wall-clock (their sandbox bill is $10K/month).

## 5. Coding RL and agentic RL below 1B: the negative results

These are the ones worth knowing before spending the compute.

1. **Plain GRPO on a small model with a sparse outcome reward can make it worse.** L20-Edu-135M: GSM8K 1.82% → 1.59% ([2606.22189](https://arxiv.org/abs/2606.22189)). Single run, honestly labeled as a failure mode rather than a bound — but it is the closest published analogue to a 7.5M model with no format floor.
2. **RL can destroy a model that is already at a task-specific optimum.** At ≤1.5B with a micro-budget, math-aligned models *collapsed* under noisy RL while instruction-tuned models merely elongated CoT to farm reward ([2601.06677](https://arxiv.org/abs/2601.06677)). Directly relevant: dormouse's Engram already drives train CE to ~0 while held-out stays hard — that is a near-optimum on a memorization task, and RL against a verifiable task on top of it is exactly the regime that collapsed here.
3. **Reward shaping degenerates at small scale.** Linter-only shaping → shorter completions with fewer lint errors and *no* reliable functional gain ([2605.30478](https://arxiv.org/abs/2605.30478)). Complementary rewards fix it.
4. **GRPO is the wrong algorithm for small multi-turn agents.** ATOD: +4.16 over on-policy distillation, **+23.62 over GRPO**, on ALFWorld / WebShop / Search-QA ([2606.27814](https://arxiv.org/abs/2606.27814)). The mechanism is credit assignment over a long sparse horizon, which a 7.5M model cannot resolve.
5. **On-policy distillation has its own small-model failure mode**: erroneous tool calls cascade, amplifying student-teacher divergence until the teacher's token-level supervision is actively misleading ([2605.07725](https://arxiv.org/abs/2605.07725)). Fix is step-wise divergence reweighting, and the same paper shows a 0.6B student reaching 26.13% on AIME 2025 — so the fix is cheap.
6. **SLM agents loop.** "Pervasive action looping and low resolution rates" on SWE-bench at 7B, fixed by explicitly *penalizing* degenerate looping and unproductive expert consultation during RL ([2602.22124](https://arxiv.org/abs/2602.22124)). Dormouse's PonderNet is already deleted (ADR-0013), which is consistent.
7. **Format collapse is a knob, not a constant.** SimpleRL-Zoo's core small-model finding is that format reward must be tuned per base, and that Qwen-family bases self-reflect *before* RL, so Qwen-based reproductions overstate generality. Dormouse is a from-scratch non-Qwen base: assume format reward needs its own sweep, and do not read any Qwen-0.5B result as a prior.
8. **Length growth is not capability growth.** SimpleRL-Zoo: increased response length does not always correlate with verification behaviour. Track a capability metric (ChatCORE-style), not response length.
9. **Single-seed A/Bs at this scale are noise.** ufakzeka-1: seed variance ≥ the spread across every recipe tried. Dormouse A/Bs need ≥3 seeds or they measure nothing.
10. **Two independent audits say the SFT floor may be less load-bearing than the doctrine claims** — worth knowing before treating Stage 0 as sacred. (a) At 3B, GRPO variants produced *small* grounding gains; conflict-SFT and DPO produced the gains, and **after a supervised warm start the same GRPO recipe added essentially nothing further** ([2609.00925](https://arxiv.org/abs/2609.00925)). (b) In a matched small-data study, three warm-starts (SFT, OPD, …) landed in a narrow 53–54% band in-domain; what Stage-1 actually controlled was the **entropy regime** entering RL, not the endpoint ([2606.09059](https://arxiv.org/abs/2606.09059)). Counterweight: outcome rewards do not reliably make reasoning causally important or verifier-sufficient, and **a small amount of SFT before RLVR is the documented remedy** ([2604.22074](https://arxiv.org/abs/2604.22074)). Net: keep the SFT floor, but don't expect it to be the thing that does the work — and run the cheap A/B (SFT→RLVR vs RLVR-from-base) once Stage 1 exists, exactly as ORZ's result invites.
11. **Format/metric integrity fails silently at small scale.** ufakzeka-1's gate read 64/64 against an honest 34/64 because the eval data had leaked into the fix. Dormouse's own history is the same failure mode in a different place (train-CE collapse from a 24M-row n-gram memorizer while held-out stayed at 5.5). Hold out eval bytes *before* building any post-training data, and check decontamination with a script that runs before every build.

## 6. For dormouse: the recommended minimal ladder

**Verdict on Rufus-Air**: copy its four principles, not its pipeline. Its SFT-floor doctrine, learnability band, reward-reliability ordering, and "infra is part of the recipe" are all correct and all cheap to adopt. Its 8-stage serial shape, its 27B-token SFT mix, and its agent-sandbox fleet are 4–5 orders of magnitude out of reach and, more importantly, its *successor* recipes (INTELLECT-3, MiMo-V2.6, Nemotron 3) have already abandoned the serial shape in favour of one mixed RL run plus post-RL multi-teacher distillation. **Rufus-Air is the best-documented recipe, not the best-transferring one.**

**The ladder** (sizes are byte counts, anchored to nanochat d12's mixture, the only published sub-200M SFT recipe):

| # | Stage | Scale / data | Reward | Why |
|---|---|---|---|---|
| 0 | **Format + capability SFT** | 10K–100K conversations, 10–100M bytes, 2–4 epochs. Ratio ~14:1 general chat : math-with-tool-execution. Byte-exact role delimiters on control bytes; XML-tool and Python-tool sections separated (SmolLM3). Loss on assistant bytes only. | — | Buys the three things RL needs: parseable formats, breadth, and initial successes. Ship the plateau checkpoint, not the last one. |
| 1 | **Execution-grounded RLVR** | 1K–10K verified short coding/math prompts, pre-filtered to pass rate ∈ (0, 0.8]. Group 8–16, ~256 new tokens, temp 1.0. **RL LR = 5% of SFT LR**; no KL, no trust region; advantage = r − μ; rampdown to zero. Prefer process-level reward. | Binary unit tests / exact match | Hardest-to-game reward, cheapest to compute. At 0.5B, process-over-outcome was worth ~10pp. |
| 2 | **On-policy distillation** | Teacher trajectories re-rendered in dormouse's byte format; anneal from SFT toward reward. Step-wise divergence reweighting. | Teacher token supervision + task reward | The 2026 frontier for anything multi-turn at small scale, and where all four small-scale agentic papers converge. ATOD beat GRPO by 23.6 pts. |
| 3 | **DPO/APO or merge** | On-policy preference pairs, or merge 0.9/0.1 as SmolLM3 did to repair collateral damage. | Preference | Cheap insurance; SmolLM3 shipped this at 3B *instead of* RL. |
| — | **Skip until ≥100M *and* Stage 1 is clearly working** | — | judge/rubric, sandbox agent RL, RLHF, browsing | Most gameable (Rufus-Air's own ordering) and most expensive ($10K/month of sandboxes in their accounting). |

**Copy from**: nanochat (the whole SFT→RL skeleton, the masking rule, the 0.05 RL-LR fraction, the ChatCORE-style cheap gate, the tool-inside-math trick); Tülu 3 (decontamination discipline, dev/unseen eval split, publishing failures); MiMo-7B (test-difficulty-weighted dense code reward, and the thesis that RL pays only after the base is pretrained for the skill — dormouse's lever is pretraining corpus first); SimpleRL-Zoo (format reward is a per-base knob; length ≠ capability); MiMo-V2.6 / Nemotron (the mixed-RL-then-OPD tail for the ≥1B future); the small-scale RLVR papers (process rewards, mixed-complexity data, 5× sample efficiency).

**Honest uncertainty, ranked**:

1. **Zero byte-level post-training results exist at any scale.** The entire ladder is extrapolation. First dormouse-specific risk is format: verifiers that assume whitespace-invariant token text can mis-parse byte streams, and there is no tokenizer to make role delimiters unambiguous.
2. **7.5M is ~16× below the smallest published end-to-end SFT+RL pipeline** and ~60× below the smallest published RLVR *success*. The honest expectation is that Stage 1 is a learning exercise, not a capability jump, and that the growth plan (100M–1B) is the actual recipe. ufakzeka-1's seed-variance finding means ≥3 seeds per arm before concluding anything.
3. **Capacity ceilings are real, not a data gap.** ufakzeka-1 found identity tracking over long context and multi-turn arithmetic do not move at 151M under any data change. If multi-step tool use does not emerge post-training at 7.5M, that is the expected capacity outcome, not a recipe failure.
4. **Serial vs mixed is unresolved** in the literature and moot at dormouse's compute: with budget for one RL arm, run the single most verifiable task family, which every philosophy agrees on.
5. **The SFT-floor doctrine is contested at small scale** ([2609.00925](https://arxiv.org/abs/2609.00925), [2606.09059](https://arxiv.org/abs/2606.09059)). Keep Stage 0, but budget one cheap A/B (SFT→RLVR vs RLVR-from-base) once Stage 1 exists, per ORZ.
6. **Untested at small scale: browsing / open-web search RL.** Rufus-Air's Search Agent is the only published instance, it is LLM-judged (noisy by their own account), and it costs a few hundred dollars per BrowseComp pass. Nothing below 100B has been shown to do it.
7. **Dormouse-specific risk nobody has published on**: an n-gram memory table in the model (the Engram) creates a *task-specific optimum on memorization* that published small-model RL results have no analogue for — and [2601.06677](https://arxiv.org/abs/2601.06677) documents exactly that regime producing collapse. Watch train-vs-held-out separation during Stage 1, not just the reward curve.
