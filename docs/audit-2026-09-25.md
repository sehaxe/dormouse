## 3. P10 violations worth fixing (top 10, file:line)

Lens: docs/research/2026-09-25-nasa-burn-rust-practices-renamed.md rules 2/4/5/7/9.

1. `train_loop` 584 lines — train/lib.rs:445-1028. R4 (≤60). Split: snapshot/drift, warmup, quant-check, the step body, eval, ckpt.
2. `ponder_loop_step` 563 lines — fused/mod.rs:648-1210 (moot if kill list #1 executes).
3. `forward_full_state` 235 lines — loop_block.rs:141-375. R4.
4. `ponder_loop_step_arms` 340 lines — fused/mod.rs:1290-1629.
5. `arms_inner_adjoint` 155 lines — fused/backward.rs:152-306.
6. **Assertion density ≈ 0 in the train path (R5 wants ≥2/function).** loop_block.rs: 0 assertions in 375 lines. train/lib.rs step body (650-1022): 0 `assert!`/`debug_assert!` in 584 lines — invariants like `hashes.len() == b*t*3`, `g_vec.len() == uniq.len()*dim` are checked by silent `if` (lib.rs:875) that *skips the update* on mismatch instead of failing. That silent skip is the pretrain-v21 failure shape again, one layer up.
7. **Heap allocations in the step loop** (research rule 4): offload.rs:132 (`block` vec per update), offload.rs:362-364 (`rows` Vec + `from_data` per step), train/lib.rs:874 (`g_vec` per host step), train/lib.rs:667 (`pshift` rebuilt per step), data/lib.rs:308-323 (`hashes` Vec per batch). All host-side and small, but they are the documented rule and trivially hoistable to init-sized buffers.
8. **Silent fallback chain in `HostNgram::from_bytes`** — offload.rs:187-213: returns `Option` and the caller (train/lib.rs:516-528) prints one line and **starts fresh tables** on any mismatch. For a 37 GB sidecar, "v1 layout? — starting fresh" should be a hard error, not a warning; the v21 incident is the precedent.
9. `unsafe { std::slice::from_raw_parts }` — fused/backward.rs:118-121, gated on an env var, not `#[cfg(test)]`/`debug_assertions`; a stray `DM_FUSED_BWD_DEBUG=1` in a release run reads OOB-truncated buffers. Debug-only in intent, not in mechanism.
10. **Validating fields nothing reads** — config/validation.rs:14-16 + override.rs:45-51 enforce ranges for `ponder_w/rec_w/guard_w/keep_frac/dropout/rope_base` (dead per §1). C-VALIDATE applied to dead knobs is worse than no validation: it manufactures confidence in a surface that does nothing. (Good news: **no `dyn` in any dormouse hot path** — enum dispatch (`LinearLikeInner`, `ActFormat`) and const-generic burn tensors everywhere; rule 8 is already met.)

## Verdict

Adopt-with-changes, aimed at the repo not an idea: the doctrine is real but
enforced asymmetrically — loudly for mechanisms (fused got measured and lost;
max_iter got measured and won), silently for code (gr.rs, the offload optimizer
swap, dead config fields, empty history.tsv all shipped without one). The
single highest-leverage act is not a deletion, it is the fused gate: the
direct-adjoint kernels are already written, unwired, and are the documented
cause of the only confirm-tier loss on record. Wire them, run the 50-step A/B,
and either fused earns its 7,900 LOC or the largest deletion in repo history is
pre-justified by measurements that already exist.
