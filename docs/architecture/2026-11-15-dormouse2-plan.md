# dormouse 2: план большого рефактора

**Дата:** 2026-11-15. **Статус:** план, код не начат.

## 1. Зачем — и почему не «переписать красиво»

За последние месяцы нас девять раз укусил один и тот же класс дефекта:
**код делает не то, что написано в его же докстринге, и это не видно ни в логах,
ни в тестах** (ADR-0011: SILENT = дефект).

| дефект | что произошло | что бы его поймало |
|---|---|---|
| Muon | loop-плечи получали 0.7-17% шага AdamW | счётчик `update_norm_ratio` с громким порогом |
| `use_kda=false` | «KDA-плечо» на самом деле = **ноль внимания** | тест «механизм вызван» по счётчику |
| full attention без rope | loss 4.28 → 16.4 | property-тест: перестановка входов меняет выход |
| KDA 3126 fwd / 0 bwd | прогон вообще не учился | счётчик bwd + тест «градиент не ноль» |
| mHC init | `H_res = J/n` вместо `I` | тест «идентичность на инициализации» |
| SIGReg | 256 строк на ковариацию 768 → 67% терма константа | тест ранга матрицы |
| export | bf16 уехал с меткой «ternary» | round-trip тест формата |
| `bpb_fin=0.000` | метрика молча не считалась | один модуль метрик, отказ при нуле |
| id-коллизия в HTML | секция затенила скрипт, страница умерла | вне нашего кода, но тот же класс |

Вывод: рефактор нужен не ради «чистоты», а чтобы **эти девять классов
перестали быть возможными**. Красивый код, в котором те же девять дефектов
по-прежнему невидимы, бесполезен.

## 2. Пять принципов (каждый — против конкретного класса дефекта)

**P1. Детерминированные проверки вместо прозы.** Любая коррекция превращается в
lint-правило, тест или отказ в рантайме — не в абзац в AGENTS.md. Проза не
исполняется, код исполняется.

**P2. Механизм, который не доложил, что он работал, считается неработающим.**
Каждый флаг обязан увеличить счётчик, который попадает в строку лога. Тест
падает, если счётчик нулевой при включённом флаге. Это ловит «флаг не дошёл до
кода» — наш самый частый баг.

**P3. Отказ вместо тихого фолбэка.** Любая комбинация, которая не поддержана,
падает с текстом, называющим выход. Никаких «наверное, сработает».

**P4. Внешний якорь для любой числовой математики.** Тест сверяется с
реализацией, посчитанной **вне** этого репозитория (математика, бумага,
независимый код), а не с золотым значением, снятым с собственного прогона.
Свой golden — это тест «код равен самому себе».

**P5. Один источник истины на каждое понятие.** Одна метрика BPB, один
упаковщик 4 бит, один набор квантайзеров, одна функция потерь. Дубли — это
место, где одна копия исправлена, а другая нет.

## 3. Структура

```
dormouse2/
  core/          # ничего не знает про модели
    config.py        # один объект, валидация при конструировании
    counters.py      # реестр счётчиков + обязательный доклад
    errors.py        # LoudError с «Escape: ...»
    registry.py      # компоненты по имени, без if-elif по всему коду
  data/
    sources.py       # bin/u16/dir/text, все с одинаковым интерфейсом
    stream.py        # батчи, resume, эпохи, стадии микса
    tokenizer.py     # обёртка над tokenizers, с fertility-отчётом
  model/
    blocks/          # transformer, kda, hybrid, loop
    ffn/             # dense, gated, tsct, bank
    attn/            # sdpa, kda, csa, hca, gdn
    quant/           # bf16, ternary, int4, mxfp4 — ОДИН пакер
    objectives/      # ntp, tst, lightmtp, fsp, ncp
    model.py         # сборка из реестра, без «если флаг, то другой класс»
  train/
    loop.py          # шаг: fwd → bwd → opt → счётчики
    optim.py         # muon, adamw, гибрид
    metrics.py       # BPB — единственное место
  post/
    sft.py, rl.py, verifiers/
  serve/             # OpenAI API, без записи промптов
  eval/              # downstream + BPB, один харнесс
  export/            # тернарный пакет + round-trip
  tests/
    gates/           # инварианты (P1-P5), отдельно от юнит-тестов
    parity/          # числовые якоря
```

Правило импорта (lint): `model/` не импортирует `train/`, `train/` не импортирует
`serve/`, `core/` не импортирует ничего из проекта. Нарушение = ошибка сборки.
Это ровно приём из доклада: два каталога, импорт между ними запрещён анализатором.

## 4. API: как выглядит запуск

```python
cfg = RunConfig.from_toml("configs/chat275.toml")   # валидируется здесь, не в шаге
run = train(cfg)                                    # один вызов, один лог
```

Модель собирается из реестра по именам компонентов
(`block="transformer"`, `attn="kda"`, `ffn="tsct"`, `objective="ntp"`), и каждый
компонент объявляет **возможности**, а не флаги:

```python
class Component(Protocol):
    name: str
    def capabilities(self) -> Capabilities: ...   # shapes, dtypes, devices, requires
    def counters(self) -> dict[str, int]: ...
```

Сборка проверяет совместимость **до** выделения памяти: если `kda` требует
`pos="none"` и `dtype="bf16"`, а конфиг даёт `pos="rope"` — отказ с именем
выхода. Это заменяет весь наш нынешний лес `_validate_*` функций.

## 5. Инварианты как исполняемые проверки

| инвариант | где живёт |
|---|---|
| каждый включённый флаг увеличил свой счётчик | `tests/gates/test_every_flag_counted.py` |
| каждый механизм с параметрами получил ненулевой градиент на шаге 1 | `tests/gates/test_grad_flows.py` |
| инициализация каждого механизма = заявленная (идентичность/дисперсия) | `tests/gates/test_init_matches_claim.py` |
| любая метрика не может быть 0.000 без явного «пусто» | `tests/gates/test_metrics_nonzero.py` |
| экспорт: round-trip формата бит-в-бит | `tests/gates/test_export_roundtrip.py` |
| числовая математика сверена с внешним якорем | `tests/parity/*` |
| импортные границы каталогов | lint-правило, не тест |

## 6. Миграция: удушение, не большой взрыв

Рефактор «с нуля» убьёт работающие прогоны и потеряет знания. Поэтому:

1. **`dormouse2/` создаётся рядом**, `port/` продолжает работать.
2. Каждый модуль переносится **по одному**, с парным тестом: старый и новый
   дают одинаковый результат на общем входе (бит-в-бит там, где это возможно).
3. Переносится только то, что **используется живым рецептом**. Остальное
   удаляется с записью причины (см. §7).
4. Когда `dormouse2` покрывает рецепт целиком — прогон на 120 МБ проверяет
   равенство BPB с `port/`, и только тогда `port/` уходит в архив.

Порядок переноса (по ценности, не по красоте):
`core` → `data` → `model.ffn` → `model.attn` → `train` → `eval` → `post` →
`export` → `serve`.

## 7. Что удаляется, а не переносится

Переписать — это в том числе **не тащить**. Кандидаты на удаление (у каждого
есть замер или причина):

- MoE-банк в текущем виде (13.7 кБ/с против 87 dense) — оставить как
  эксперимент в `experiments/`, вне основного пакета;
- loops (`max_iter>1`) — проиграли на трёх осях;
- mHC/AttnRes — до переприсвоения инициализации и нового A/B;
- TST/SIGReg — сейчас перемеряются; в основную ветку только при выигрыше;
- ByteFlow-патчи — заменены токенизатором;
- 90 ГБ «code», которого нет — не наш код, но урок: проверять данные до обучения.

## 8. Риски и цена

| риск | смягчение |
|---|---|
| рефактор съест недели | переносится только живой рецепт; остальное архив |
| новый код повторит старые баги | парные тесты старый/новый + пять принципов |
| прогоны остановятся | `port/` работает до последнего дня |
| «чистота» победит результат | критерий готовности — равенство BPB и скорости, а не число файлов |

Оценка: **7-10 рабочих дней** на покрытие живого рецепта (core, data, model,
train, eval), ещё 3-4 дня на post/export/serve. Первый переносимый модуль —
`core/counters.py`, потому что P2 (механизм обязан доложить) ловит больше всего
наших дефектов и почти ничего не стоит.
