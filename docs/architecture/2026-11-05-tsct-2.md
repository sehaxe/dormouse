# 2026-11-05 — TSCT-2: три механизма, которые должны вернуть банк в игру

## Что TSCT делает сейчас (по коду, не по докам)

`experts.py:679`:

```python
g = (x @ gate_u) * gate_s      # gate_u ОБЩИЙ для всех экспертов, [d, 192]
u = (x @ up_u)   * up_s        # up_u   ОБЩИЙ, [d, 192]
h = silu(g) * u
y = h @ v                      # v ПЕР-ЭКСПЕРТНЫЙ, [r=64, f=4096]
```

То есть:

| часть эксперта | параметров | общая? |
|---|---:|---|
| входная специализация (`gate_s`, `up_s`) | **384** (2×192) | **диагональ**, а не матрица |
| выходная запись (`v`) | 262 144 | пер-экспертная |
| банк (512 экспертов) | 134 479 872 | — |

**Ключевое: эксперт различает других только (а) покоординатным гейном на общих 192
признаках и (б) своей выходной матрицей.** Два эксперта не могут смотреть на
*разные* подпространства входа — они смотрят на одни и те же 192 общих признака
и лишь по-разному их взвешивают. Это структурное ограничение, и оно объясняет,
почему банк не бьёт плотную модель при нашем бюджете: маршрутизация выбирает
«как писать», но не «что искать».

## Три механизма

### 1. Пер-экспертное входное подпространство (`tsct_expert_basis`)

```python
w_j: [64, 192]                       # 12 288 параметров вместо 384
g = ((x @ gate_u) @ w_j.T) * gate_s   # эксперт выбирает СВОИ 64 из 192 признаков
u = ((x @ up_u)   @ w_j.T) * up_s
```

Цена: +12 288 × 512 = **+6.3M** (4.7% банка, +3% всей модели).
Смысл: 64×192 — это полноценный низкоранговый селектор, а не диагональ.

### 2. Контроль голодания экспертов (`tsct_expert_lr`)

Эксперт получает 32 назначения за шаг против 8192 токенов у плотного слоя.
Холодный эксперт не тренируется, потому что его градиент меньше.

```
lr_j = lr · (1 + tsct_expert_lr · (mean(L) / max(L_j, 1) - 1))
```

где `L_j` — счётчик назначений за окно (он уже есть для LFB). Механизм
бесплатный по параметрам и памяти, и прямо бьёт в измеренную проблему
(189 из 512 живых).

### 3. Переинициализация мёртвых экспертов (`tsct_expert_revive`)

Раз в `tsct_revive_every` шагов: эксперт с наименьшим счётом получает веса
самого загруженного эксперта плюс шум `σ = tsct_revive_noise · std(v_hot)`,
и его счётчик и bias обнуляются.

Это не «магия», а известный приём (lottery/reinit в разреженных моделях): мёртвый
эксперт не может выйти из ямы градиентом, потому что градиента нет. Гейт: доля
живых экспертов обязана вырасти, иначе механизм инертен и должен быть удалён.

## Что каждый механизм должен доказать

| механизм | гейт | правило вердикта |
|---|---|---|
| `tsct_expert_basis` | OFF бит-идентичен; ON паритет 1e-6; +6.3M параметров подтверждены | BPB ниже контроля на 2× разброса за 2000 шагов × 3 сида |
| `tsct_expert_lr` | OFF бит-идентичен; счётчики на устройстве; ноль host-синков | то же + доля живых ≥ 70% |
| `tsct_expert_revive` | детерминизм (сид); веса донора копируются точно до шума | доля живых ≥ 85%, BPB не хуже контроля |

## Почему это может закрыть разрыв 0.046 BPB

```
плотная 81M:   каждый токен обновляет ВСЕ 81M параметров
банк 199M:     токен обновляет 2 эксперта = 0.5M параметров (0.26%)
               при 32 назначениях на эксперта за шаг
```

Разрыв не в том, что банк «плохо факторизован», а в том, что **ёмкость банка
не получает градиента**. Механизмы 2 и 3 адресуют это напрямую, механизм 1
делает оставшиеся живые эксперты содержательнее.

Если после всех трёх банк всё равно проигрывает плотной — вывод окончательный:
при 22 ГБ данных TSCT неприменим, и он остаётся флагом для масштаба ≥10× данных.
