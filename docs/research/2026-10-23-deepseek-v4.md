# DeepSeek-V4 / V4.1 — what is actually in it, and what (if anything) we should port

**Date:** 2026-10-23 · **Question:** the 2026 DeepSeek line, V4 and V4.1, and the one mechanism
worth porting into dormouse.
**Answer, first line:** the technical reports **exist**, and they are papers, not just model cards —
**V4 = arXiv:2606.19348** (submitted 2026-04-26) and **V4.1 = arXiv:2609.19969** (submitted
2026-09-17). There is **no monolithic `DeepSeek-V4` code repository**; weights are open on
HuggingFace and the systems pieces are open as component repos.

Every claim below is tagged **VERIFIED** (with the section or URL it came from) or
**SPECULATION** (my inference, explicitly marked). Section numbers refer to the arXiv HTML of the
two papers, read 2026-10-23.

---

## TL;DR

1. V4 is **not** "V3 plus data". Three real architecture changes: **MLA is replaced by a hybrid
   CSA/HCA compressed-sparse attention**, the residual stream becomes **mHC** (Sinkhorn-projected
   doubly-stochastic hyper-connections), and **Muon** replaces AdamW for matrices. **[VERIFIED]**
2. Almost all of the *new* engineering is **KV-cache and prefill cost** — a problem dormouse does
   not have, because KDA's state is O(1) in sequence length. **[VERIFIED for them; our state from
   `docs/architecture/2026-10-23-final-architecture.md`]**
3. Two of the mechanisms people associate with V4 — **mHC** and **aux-loss-free MoE** — we either
   already run (mHC, measured −0.078 BPB at 600 steps) or **claim to run but do not have in code**
   (the LFB bias controller: no `lfb`/`route_bias`/`bias_update` symbol exists in `crates/`).
   **[VERIFIED, `grep`]**
4. Engram and DSpark, which V4.1 makes first-class, are already in our tree — and V4.1's Engram
   update rule (**Nesterov momentum + Sinkhorn**) is the same rule our host-table path already
   uses. That is a genuine external confirmation of a choice we made alone. **[VERIFIED, §2.4.2 /
   §4.2.2 vs `AGENTS.md` §3.5 item 1]**
5. **The port I recommend: the aux-loss-free routing bias** (~40-80 LOC, quality/stability), with
   `sqrt(softplus)` affinity as a 3-line rider. Expected effect at 105M: **small or zero** — its
   value is that our shipped router currently has *no* balancing pressure at all, and the docs say
   otherwise. Budget one 3-seed arm; a tie deletes it, per §1.2.

## 2. Architecture, each mechanism with its source line

### 2.1 Attention — **MLA is gone**; CSA + HCA hybrid

> "Compared with the DeepSeek-V3 architecture … we design a hybrid attention mechanism combining
> Compressed Sparse Attention (CSA) and Heavily Compressed Attention (HCA)." — V4 §1 **[VERIFIED]**

MLA is not mentioned anywhere in V4's architecture chapter (§2). The three "designs inherited from
V3" are MoE, MTP and the training data pipeline — attention is **not** among them (§2.1).
**[VERIFIED]**

| mechanism | what it does | numbers | source |
|---|---|---|---|
| **CSA** | compresses each **m** KV entries into 1 using learned softmax weights + positional biases (overlapping windows, so net compression = 1/m), then runs **DSA** sparse selection over the compressed entries, then **shared-KV MQA** | Flash: m=4, top-k **512**, n_hI=64, c^I=128, n_h=64, **c=512**, **d_c=1024**, g=8, d_g=1024. Pro: top-k **1024**, n_h=128, d_c=1536, g=16 | §2.3.1, §4.2.1 **[VERIFIED]** |
| **HCA** | much heavier compression, **dense** attention (no sparse selection), plus a small sliding-window branch | m′ = **128** for both models | §2.3.2, §4.2.1 **[VERIFIED]** |
| **extras** | RMSNorm on every q head and the single compressed-KV head (this is what replaces QK-Clip); **partial RoPE on the last 64 dims**, plus RoPE with position −i on the outputs; sliding window n_win=**128**; attention sink logits | — | §2.3.3, §2.4 **[VERIFIED]** |
| **grouped output projection** | split n_h outputs into g groups, project each to d_g < c·n_h/g, then concatenate and project to d | — | §2.3.1 **[VERIFIED]** |

**On "what latent dim":** there is no MLA latent to quote. The nearest analogue is the **query
compression dimension d_c = 1024 (Flash) / 1536 (Pro)**, with head dim c = 512; the KV side is
compressed *along the sequence*, not into a latent vector. **[VERIFIED, §4.2.1]**
Note: V4.1 still *cites* FlashMLA kernels in its inference section (§3.2), so MLA-shaped kernels may
survive in the serving stack for the SWA/full-attention path; I did not read §3.2 and do not claim
it either way. **[SPECULATION: unverified]**

### 2.2 MoE — same DeepSeekMoE skeleton, two changes

- **Shape:** 1 shared expert + **256 routed** (Flash, expert intermediate 2048) / **384 routed**
  (Pro, 3072), **top-6 active**, fine-grained. **[VERIFIED, §4.2.1]**
- **Router activation changed:** Sigmoid → **`Sqrt(Softplus(·))`** for the affinity scores.
  **[VERIFIED, §2.1]** This is the only routing-score change in the paper, and it is stated without
  an ablation.
- **Hash routing replaces the dense FFN** in the first **3** MoE layers (target expert from a hash of
  the input token id). **[VERIFIED, §2.1, §4.2.1]**
- **Balancing:** aux-loss-free bias strategy **retained**, bias update speed **0.001**, plus a small
  **sequence-wise balance loss at weight 1e-4**. **[VERIFIED, §2.1, §4.2.2]**
- **MTP depth = 1** and "identical to DeepSeek-V3 … without modification". **[VERIFIED, §2.1, §4.2.1]**

### 2.3 mHC — the residual stream

- Residual width expanded by **n_hc = 4**; per layer `X_{l+1} = B_l X_l + C_l F_l(A_l X_l)`.
  **[VERIFIED, §2.2]**
- **B_l is projected onto the Birkhoff polytope** (doubly stochastic: rows and columns sum to 1,
  non-negative) by **Sinkhorn-Knopp, t_max = 20**. This bounds ‖B‖₂ ≤ 1 (non-expansive) and the set
  is closed under multiplication. **[VERIFIED, §2.2]**
- `A_l = σ(Ã)`, `C_l = 2σ(C̃)` — both non-negative and bounded. **[VERIFIED, §2.2]**
- Coefficients are **dynamic** (input-dependent) plus static biases, with learnable gating factors
  α initialised small; input is `RMSNorm(vec(X_l))`. **[VERIFIED, §2.2]**

### 2.4 Optimizer

- **Muon** for all matrix parameters; **AdamW** only for embedding, prediction head, RMSNorm weights,
  biases, and mHC's static biases/gating factors. **[VERIFIED, §2.4]**
- **Hybrid Newton–Schulz**: 10 iterations in two stages — 8 × `(3.4445, −4.7750, 2.0315)`, then
  2 × `(2, −1.5, 0.5)` to pin singular values at 1. **[VERIFIED, §2.4]**
- Momentum 0.95, weight decay 0.1, update RMS rescaled to **0.18** so the AdamW LR transfers.
  **[VERIFIED, §4.2.2]**
- **QK-Clip is not used** — the q/K RMSNorm makes it unnecessary. **[VERIFIED, §2.4]**
- **V4.1 adds:** **head-wise Muon** for Q and K (per-head preconditioners; claims to beat vanilla
  Muon, "validated in GLM 5 and Kimi-K3"), and a **Sinkhorn-balanced momentum update** (K=11,
  τ=1e-3) for **Engram tables, token embedding and prediction head** instead of Adam — same memory
  as Muon (one momentum buffer) and "empirically outperforming Adam". **[VERIFIED, V4.1 §2.5,
  §4.2.2]**

### 2.5 Precision, context, stability

| item | value | source |
|---|---|---|
| routed expert **weights** | **FP4**, with FP4 QAT (FP32 master → FP4 → dequantised to FP8 for compute; the FP4→FP8 dequant is stated lossless) | V4 §1, §9.2.1 **[VERIFIED]** |
| KV storage | **BF16 for the RoPE dims + FP8 for the rest** ≈ half of pure BF16 | V4 §2.3.4 **[VERIFIED]** |
| indexer | FP4 attention compute; index scores FP32→BF16 = **2× top-k selector speedup at 99.7% recall** | V4 §2.3.4, §9.2.1 **[VERIFIED]** |
| context | **1M native**; trained 4K → 16K → 64K → 1M; V4 warms up **dense for 1T tokens** before sparse at 64K | V4 §4.2.2 **[VERIFIED]** |
| V4.1 context training | **sparse attention from scratch at 64K**, extended to 1M at 34T tokens | V4.1 §4.2.2 **[VERIFIED]** |
| tokens | V4-Flash **32T**, V4-Pro **33T**; V4.1 **45T multimodal** | V4 §4.2.2, V4.1 §4.2.2 **[VERIFIED]** |
| stability | **Anticipatory Routing** (route with θ_{t−Δt} while computing features with θ_t; ~20% overhead when active) + **SwiGLU clamp to [−10, 10]**, gate upper bound 10 | V4 §4.2.3 **[VERIFIED]** |
| **backbone training dtype** | **not stated** in the sections I read. "Mixed precision" returns no passage; BF16 appears only for KV storage and EP combine (FP8 dispatch + BF16 combine) | V4 §2.3.4, §3.1 **[VERIFIED as absent from what I read; unknown]** |

## 4. Delta vs V3 / V3.2 — what is genuinely new

| # | change | new in V4? | new in V4.1? |
|---|---|---|---|
| 1 | **Attention: MLA → CSA + HCA** (compressed KV + sparse selection + MQA + grouped output projection) | **yes, the big one** | refined to **CSA2** (cross-layer KV/index reuse, hierarchical indexer) |
| 2 | **Residual: mHC** — Birkhoff-projected B, sigmoid-bounded A/C, n_hc=4, dynamic coefficients | **yes** | **Single-Pass mHC** (shift A by one block) + Mega-mHC kernel |
| 3 | **Optimizer: Muon** for matrices, hybrid NS, no QK-Clip | **yes** | head-wise Muon (Q/K), Sinkhorn update for embedding/head/Engram |
| 4 | **Router affinity `Sqrt(Softplus)`**; first 3 layers hash-routed | **yes** | modality-specific balancing (image vs text) |
| 5 | **Stability: anticipatory routing + SwiGLU clamp** | **yes** | — |
| 6 | **Lower precision:** FP4 expert weights; BF16/FP8 mixed KV | **yes** | **FP4 main KV** |
| 7 | **CED** (20-layer causal encoder + 20-layer decoder; decoder global KV projected from the encoder's last hidden state) | no | **yes** |
| 8 | **Engram** (196B conditional memory) and **DSpark** (replaces MTP) | no — DSpark ships as a separate V4 checkpoint | **yes, first-class** |
| 9 | **Scale/data:** 671B/37B → 1.6T/49B; 32–33T tokens | scale | 45T multimodal |

**So: is V4 "mostly scale + data"?** No — items 1–3 are architecture, and item 1 is a replacement,
not an extension. But **for dormouse the transferable fraction is small**, because items 1, 6, 7 and
half of 8 are about a per-token KV cache and a prompt-prefill phase that we do not have.
**[VERIFIED for the delta; SPECULATION for the "for us" judgement, argued in §5]**

## 6. The one mechanism to port

**Port the aux-loss-free routing bias** (V4 §2.1 / §4.2.2: per-expert bias added to the selection
logits, updated at speed 0.001 from the assignment histogram, **not** back-propagated), with
`Sqrt(Softplus)` affinity as a 3-line rider and the 1e-4 sequence-wise balance term optional.

**Why this one and not the attention stack:**
- It is the only V4 mechanism we both **lack** and **can use**: 256 experts at top-2 is a 0.8%
  routing density, exactly the regime where a dead expert is invisible in the loss and expensive in
  quality.
- It is **cheap and reversible**: ~40-80 LOC (bias vector `[E]`, histogram on device, add-before-
  top-k, config field, a probe counter per §1.1, one unit test). No new kernel, no new memory of
  consequence.
- It makes an existing doc claim true instead of false, which is worth more than a tied A/B.
- Everything else is either already ours (mHC, Engram, DSpark, Muon+, MTP) or solves a problem we
  do not have (CSA/HCA, CED, FP4 KV, 890 B/token).

**Expected effect at 100M–1B:** honest answer — **near zero BPB unless the router is currently
collapsed**, in which case it is worth more than any of the recent structural arms. There is no
small-scale evidence either way in the paper; DeepSeek's numbers are at 671B–1.6T. Treat it as
insurance plus a diagnostic, not as a quality win. **SPECULATION.**
**Cost of finding out:** one 3-seed, 600-step arm on the existing harness — the cheapest row in the
A/B queue. If it ties, §1.2 deletes it and the doc claim gets struck instead.

**Runner-up, if the goal is throughput rather than quality:** **Single-Pass mHC + a fused
residual/mixing/coefficient kernel** (400-800 LOC). It is the only V4 item that attacks our measured
pathology — 13.3% mean GPU utilisation, launch-bound, GEMMs 2-5% of a step — and V4.1's own
motivation for Single-Pass is precisely activation-memory traffic, not model quality. It is a
project, not an arm.

**Rejected, with the reason:**
- **CSA/HCA, CED, FP4 KV, SWA replay, 890 B/token** — no per-token KV and no prefill in a byte-level
  looped LM. Porting them would mean replacing KDA with a worse fit for a 16 GB card.
- **MLA** — we are about to build the thing V4 removed. Still worth building for the 1B width
  budget (it is a d² → d·r saving and nothing else), but stop calling it "matching DeepSeek".
- **n_hc = 4** — a config change on a mechanism that already won and whose effect decayed from
  −0.078 (600 steps) to −0.028 (2000). VRAM is already +40% at K=2; test only if VRAM is free.
- **Hash routing** — we have no dense FFN layers to replace.
- **Sinkhorn embedding/head update** — 256-token vocab; there is no memory to save.
- **Anticipatory routing** — built for trillion-parameter routing outliers; our NaN class is
  overfit-corpus (`AGENTS.md` §2.3), not routing.
- **SwiGLU clamp** — 1 line, but it would confound the routing arm; run it as its own arm if the
  NaN class recurs on real data.

## 7. Open questions

1. **Backbone training dtype is not stated** in V4 §4.2.2 or V4.1 §4.2.2. FP8 dispatch/BF16 combine
   is communication, not compute. Anyone claiming "V4 trains in FP8" from these papers is guessing.
2. **No decode-speed number and no DSpark acceptance length** are published. The 890 B/token and
   27%/10% figures are cost ratios at 1M, not throughput at short context.
3. **1017 has no report.** Architecture unchanged per TUD; benchmark deltas are vendor-reported.
4. **Why 284B vs 291B and 748B vs 763B** — unexplained in both papers.
5. **Does `sqrt(softplus)` matter?** No ablation in V4. It is stated as a fact, not measured.
6. **Our own LFB claim** needs a decision: implement the bias controller, or strike the ✅ in
   `docs/architecture/2026-10-23-1b-in-a-week.md:75`. Leaving both is the §1.7 defect.
