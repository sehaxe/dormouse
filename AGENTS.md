# AGENTS.md

## Mission

dormouse = byte-level LM trainer in Rust (burn 0.22.0-pre.3 + cubecl CUDA) with max efficiency per FLOP/byte: all-bf16 storage+compute (f32 acc), PonderNet adaptive compute, n-gram memory, sparse attention, low-rank TSCT experts. Target hardware: 16 GB VRAM (5060 Ti) + 64 GB host RAM. Goal: train the biggest possible smart model on that box, optionally offloading to RAM without latency.

## Repo layout

- `crates/dormouse-core` — model: `DormouseModel` = Embedding → `LoopBlock` → RMSNorm → lm_head (all LinearLike). LoopBlock per iteration: controller (sigmoid w_attn/w_mem/w_ffn + softmax expert blend) → shared attention (KDA gated-delta + MSA top-k sparse, learned sigmoid blend) + Engram (FNV-hashed n-gram tables) + n_experts TSCT (spectral low-rank) FFNs → ReZero residual (or Gated Residual when `use_gr`) → halt head → PonderNet halting. `config.rs` presets: `small`, `base`, `one_b`.
- `crates/dormouse-data` — streaming byte stream (next-byte LM, vocab 256), seeded Fisher-Yates file shuffle, deterministic train/eval split.
- `crates/dormouse-train` — CUDA autodiff loop: Muon+ mixed optimizer (policy + groups in `src/optim.rs`), burnpack `.bin` checkpoints, resume by reusing `ckpt_name`, quantization A/B probe, pool cleanup.
- `crates/dormouse-cli` — bins `train`, `generate`, `serve` (checkpoints dir + `--ckpt-name`, preset).
- `crates/dormouse-bench`, `dormouse-serve` — bench harness, HTTP serve.

## Env knobs (runtime switches, no rebuild)

- `BF16=1` — bf16 activations/weights (weights fp32→bf16 cast per forward). Off by default; burn-ndarray has no bf16 so CPU runs stay fp32.
- `DM_NO_KDA` / `DM_KDA`, `DM_NO_MSA` / `DM_MSA`, `DM_NO_ENGRAM` — disable/force-enable attention arms (bisect/A-B). All presets set `use_kda`/`use_msa` true (config.rs doc comments claiming "default off" are stale — the values say otherwise), so `DM_NO_*` is the practical switch; `DM_*` only matters if a preset is flipped to false. Engram default on (`DM_NO_ENGRAM` off).
- `DM_QUANT_DEBUG` — print quant format of every LinearLike forward.
- `OPT=mix|mix-adan|adan|adamw|muon` — optimizer (see below, `optim.rs`). Default `mix`.
- `DM_FACTORS_FALLBACK=1` — drop expert TSCT u/v factors from the Muon+ group to the fallback optimizer (A/B: the report kept elongated low-rank projections on AdamW).
- `DM_RETRACT_EVERY` / `DM_RETRACT_ITERS` — TSCT U/V ortho maintenance cadence (default every 1 step, NS 3 iters; the plan's `max_ortho` monitor falls back to fp32 factors above 1e-3, checked every 50 steps).
- `DM_STRESS=1` — stability stress protocol (report §3.3): constant LR at `DM_STRESS_LR`× the base, loss-spike counter (201-step median + 0.1), p99.9 pre-clip grad norm; `DM_STRESS_EVERY` log cadence (default 50).

## GPU/CUDA quirks (hard-won, do not rediscover)

- **Never dynamically slice a 4D autodiff tensor**: cubecl on sm_120 crashes with `CUDA_ERROR_ILLEGAL_ADDRESS`. This is why L_Rec is accumulated inside `loop_block.forward_full_state` (per-step CE on `[b*t,d]` reshapes) instead of materializing `[N,b,t,d]` step hiddens and slicing them. Keep it that way.
- **bf16 logits NaN**: final norm + lm_head must run in fp32 even in BF16 mode (`model.rs` casts to F32 before the head). Loop-internal L_Rec logits likewise fp32.
- **cubecl memory pool is high-water**: reserves pages for every size ever seen, never frees → long runs OOM. `train_loop` calls `memory_cleanup()` periodically; `init_pools` (ExclusivePages) must run before the first allocation. Pool is NOT enabled by default.
- **burn-msa `gradient_detach` leaks autodiff nodes** (~74/step, OOM in long runs) on pre.3. Keep `gradient_detach = false` (index branch trains, tiny cost).
- `LinearLike` pads out_features to a multiple of 4 (cubek matmul vectorization, N%4==0) then slices back; keep the slice on all new heads.
- **Training instability on this box (pre-existing, open)**: NaN episodes appear in ANY config (fp32+adamw included, `DM_QUANT=fp32 OPT=adamw` 150-step-clean runs were lucky seeds) once the model overfits hard — with the 0.85 MB test corpus loss hits ~0.5 by step 50 and the KDA recurrence goes NaN (a_log overflow fixed with a clamp in burn-kda 2026-08-29; deeper overflow path not isolated — bisect showed `DM_NO_KDA=1` stays clean through deep overfit). Moonshot/FLA decay init (`a_log=-3`, `b_alpha=1.0`) + clamp measurably extended the clean window (110+ steps, Muon+, fp32, no NaN on 2026-08-29 vs 45-127 before). Fp8 quant (sm_120 default) additionally degrades at overfit (range overflow). This is an overfit-corpus artifact: on a real loss profile (3+) it should not trigger; verify on real data before chasing further. OOM flood follows NaN episodes (~10-50 steps later); `memory_cleanup` right after NaN makes it worse (pool goes bad), so NaN-skip does NOT call cleanup.
- **bf16 compute path on CUDA**: fixed 2026-08-29. The rule: mixed-dtype ops (bf16 activations x fp32 weights, bf16+f32 adds) NaN on this stack, so `BF16=1` computes in fp32 and stores activations in bf16 — cast to fp32 before every Linear (controller, KDA, halt head, SpectralLinear inputs) and cast the residual/GR writes back to the activation dtype. Verified: 60 steps, 0 NaN, loss 5.53→2.21. Caveats: MSA/Engram kernels are f32-only (inputs cast), the KDA fused chunked kernel is f32-only (falls back to tensor ops), and bf16 runs are slower than fp32 (cast copies + tensor-path KDA) — revisit fused bf16 kernels for speed. Fp8 quant (sm_120 default) still degrades at overfit; `DM_QUANT=fp32` is the stable combo. This is also why Muon+ NS stays off the [d,d] projections (fp32 NS on [768,768] costs ~40 s/step — tensor cores need the bf16 path).
- TSCT ortho: bf16 plan wants U/V retract every 1 step + `max_ortho` monitor with fp32 fallback if ortho > 1e-3 — but `param.rs::retract_model` is a no-op, nothing calls it yet. burn-spectral `polar_orthogonalize` (Muon+ §1-style NS) and burn-sct QR retract both exist; wiring is pending.

## Design playbook: what to adapt from Qwen3.8-Flash-Next (tech_report.pdf)

The report's architecture (125B MoE, 6B active, 51B n-gram params off-accelerator) is the closest published match to dormouse's goals. Adaptations ranked by payoff for a 16 GB GPU + 64 GB RAM box:

1. **RAM offload via host-prefetched n-gram tables (the big one)**. Qwen stores 51B n-gram embedding params in host memory: deterministic hash addressing → async prefetch of the next batch's rows (pinned memory, separate CUDA stream) overlapped with compute, so host RAM is a latency-free extension of VRAM. dormouse's Engram already uses deterministic FNV keys — scale the 3×4096 tables up (millions of slots, bf16 rows) and keep them in RAM, prefetch per-batch. Rule from the report: n-gram tables train with Adam, weight decay disabled. Loss drops monotonically with vocab scale; downstream saturates — evaluate both.
2. **Gated Residual (GR)**: widen the residual stream to 4 branches; read = elementwise sigmoid gate on a low-rank bottleneck (rank d/8) over group-RMSNorm'd branches; write = one scalar per branch; no branch-mixing operator Hres. Replaces ReZero scale and pre-norm. Report: −0.026 loss at 276B tokens, zero loss spikes at 4× LR, larger LR/batch become safe, no qk-clip/SwiGLU-clip needed (gates bound activations). Cheap: scalar writes, one low-rank read. FP8 residual state later halves traffic. Also `GatedNorm` (RMSNorm ⊙ σ(W2 SiLU(W1 RMSNorm(u)))) helps everywhere. Do NOT use sparse writes (top-2 branches): fine in pretraining, degrades post-training. **Wired as `use_gr` config flag (off by default for checkpoint compatibility; `crates/dormouse-core/src/gr.rs`, all slicing 2D/3D — a 4D gate tensor would crash sm_120), convergence-tested on NdArray.**
3. **Muon+ (burn-fused `burn-muon-plus`, arXiv 2602.21545)**: Muon + post-polar ColRow normalization, fused CUDA kernels, hybrid 2D→Muon+/1D→AdamW. **Wired into `dormouse-train` as the default optimizer** (`OPT=mix`, policy in `train/src/optim.rs`), with the report's param-group routing: Muon+ ColRow on 2D linear maps only (attn q/k/v/o, GDN projections, expert fc1/fc2, out_proj); AdamW for embeddings, output head, controller/router, low-rank projections (orthogonalization hurts them); n-gram tables on Adam with weight decay disabled. `ns_steps=8` (report's stability choice; Muon+ default is 5). `validate_routing` re-checks the policy against the live module tree at startup — a stale marker (module renamed) fails loudly instead of silently falling back to AdamW. Report deltas still open: split fused params (qkv per-head, SwiGLU gate/up halves) BEFORE orthogonalization — fusing mixes singular directions; capture the step in a CUDA graph (hundreds of small kernels after split). Skip the report's Polar Express schedule and γ = 0.2·max(A,B): Muon+ already ships its own validated recipe (quintic NS_COEFFS, Bernstein factor max(1, m/n)^0.5). Fallback-group alternative: Adan (arXiv 2208.06677) via `OPT=adan`/`OPT=mix-adan` (Nesterov + gradient-difference, ships in burn-optim). bf16 plan already targets Muon moments bf16 + stochastic rounding, MuonQ 4-bit. Note: `param.rs::retract_model` is a no-op stub — TSCT U/V ortho maintenance is NOT actually wired into training (burn-spectral `polar_orthogonalize` is the Muon+-style NS retraction; iters is the caller's choice).
4. **Sparse attention indexer (QSA → MSA)**: train the MSA block-indexer in two stages — (a) distill the dense attention distribution (max-pooled to blocks, KL) into the indexer at high LR for ~1k steps, (b) then joint sparse training. Indexer recipe: MQA (4 q-heads, 1 shared k-head), avg-pool keys into blocks r=4, block-causal ReLU scoring, top-KB blocks + always include the tail tokens of the final incomplete block, partial RoPE. Reuse top-k indices across MTP/speculative steps. At 1M ctx: 7.6× prefill / 4.9× decode vs dense.
5. **GDN details for KDA** (already the hybrid shape dormouse uses): sigmoid output gate (not SiLU), zero-centered RMSNorm everywhere, L2-normalized q/k, decay α_t = exp[−exp(A)·softplus(Wα x + bα)]. One full-attention layer per 4 (dormouse's per-iteration router blend covers this; keep RoPE in the attention arm — NoPE → endless generation after post-training). `use_short_conv` (report's local-bias choice) was tried and REVERTED: it made fp32+AdamW NaN at ~step 60 on this box while the same recipe ran 150+ steps clean without it (measured 2026-08-29) — trace inside burn-kda before re-enabling. KDA state dtype follows the inputs (bf16 under `BF16=1`, fp32 otherwise — Moonshot FlashKDA trains bf16 state); decay init matches the Moonshot/FLA recipe (`a_log=-3`, `b_alpha=1.0` — conservative alpha~0.08 at start). FlashKDA math (K3 decay, chunked WY, chunk 16) already matches burn-kda; their CUTLASS kernels are the remaining perf delta.
6. **Hyperparameters & stability**: with Muon+GR, batch-size warmup is wasted (−18.8% extra steps, no gain) — start at target batch/LR; optimal LR/batch shift up. Refit scaling laws per architecture change (report: new recipe ends 7.8e-3 better than old-recipe hyperparams at same budget). **Stress-test protocol** (cheap, do it on 16 GB): constant LR at 2× and 4× optimal, count loss spikes (> 201-step rolling median + 0.1), p99.9 pre-clip grad norm, per-block activation max. Stability = gate/bounded activations, not clipping.
