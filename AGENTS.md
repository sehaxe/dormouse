# AGENTS.md

## Mission

dormouse = byte-level LM trainer in Rust (burn 0.22.0-pre.3 + cubecl CUDA) with max efficiency per FLOP/byte: all-bf16 storage+compute (f32 acc), PonderNet adaptive compute, n-gram memory, sparse attention, low-rank TSCT experts. Target hardware: 16 GB VRAM (5060 Ti) + 64 GB host RAM. Goal: train the biggest possible smart model on that box, optionally offloading to RAM without latency.

## Repo layout

- `crates/dormouse-core` — model: `DormouseModel` = Embedding → `LoopBlock` → RMSNorm → lm_head (all LinearLike). LoopBlock per iteration: controller (sigmoid w_attn/w_mem/w_ffn + softmax expert blend) → shared attention (KDA gated-delta + MSA top-k sparse, learned sigmoid blend) + Engram (FNV-hashed n-gram tables) + n_experts TSCT (spectral low-rank) FFNs → ReZero residual (or Gated Residual when `use_gr`) → halt head → PonderNet halting. Aux heads ON by default (`aux.rs`: JEPA EMA-teacher masked latent prediction + KoLeo; DSpark draft head for next-K tokens). Presets are flat TOML files in `configs/` (loaded by name or path; schema defaults == `small`; no Rust registry).
- `crates/dormouse-data` — streaming byte stream (next-byte LM, vocab 256), 64 MB ring refilled in 8 MB chunks, seeded Fisher-Yates file shuffle, deterministic train/eval split, parquet/images/binaries.
- `crates/dormouse-train` — CUDA autodiff loop: Muon+ mixed optimizer (policy + groups in `src/optim.rs`), burnpack `.bin` checkpoints, resume by reusing `ckpt_name` (each run also writes `<ckpt_name>.config.toml`; a resume whose resolved config differs from the snapshot hard-errors — ADR-0005, keep the original argv), quantization A/B probe, pool cleanup, host-RAM n-gram tables + CPU Adam (`src/offload.rs`), stress protocol (`src/stress.rs`).
- `crates/dormouse-cli` — bins `train`, `generate`, `serve` (checkpoints dir + `--ckpt-name`, preset). BPB scoring lives in `dormouse-train` (`pub fn bpb`).

## Knobs (typed CLI flags on `train`; `--help` for the full list)

- `--bf16` — bf16 activations/weights (weights fp32→bf16 cast per forward). Off by default; CPU runs stay fp32 (burn-ndarray has no bf16).
- `--no-kda` / `--no-msa` / `--no-engram` — disable an attention/memory arm (bisect/A-B; presets set kda/msa/engram true).
- `--quant fp32|bf16|fp16|fp8|fp4` — force the TSCT factor format (default: auto per SM).
- `--opt mix|mix-adan|adan|adamw|muon` — optimizer (see below, `optim.rs`). Default `mix`.
- `--factors-fallback` — drop expert TSCT u/v factors from the Muon+ group to the fallback optimizer.
- `--retract-every N` / `--retract-iters K` — TSCT U/V ortho maintenance cadence (default every 1 step, NS 3 iters; `max_ortho` is monitored every 500 steps, and above 1e-3 per-entry ALL factors irreversibly switch to fp32 — one-way, checks stop after the fallback).
- `--stress --stress-lr X` — stability stress protocol (report §3.3): constant LR at X× the base, loss-spike counter (201-step median + 0.1), p99.9 pre-clip grad norm; `--stress-every` log cadence (default 50).
- `--act-quant 4|8|fp4` + `--act-group N` — BitNet a4.8-style activation quantization (STE, f32 graph; `core/src/act_quant.rs`): FFN activations at the format, attention path at max(bits, 8). Verified: fp4 + group 128, 100 steps, 0 NaN, convergence == fp32.
- `--engram-ram [--engram-slots N]` — host-RAM n-gram tables (report §2.3): millions of rows in the 64 GB RAM, CPU Adam, only the batch's rows copied to the GPU (~600 KB/step). Real use: real18 = 48M rows = 1.54B memory params, 18.4 GB.
- `--host-adam-every N` — host-table Adam cadence (default 1 = every step, the report's rule; 0 = off). Each update syncs the row grads D2H; the loss-scalar read rides along. Measured cost of every-step (small/batch3/s512 smoke, 2026-09-04): +2.3% step time vs 0 (10884 vs 10637 ms) — the pipeline drain is the sync wait, not the copy. Until 2026-09-04 the update ran only on log steps (a sync-deferral side effect, tables got 1/100 of their updates) — don't regress it; trade with `--host-adam-every 5` if a run is step-time-bound.
- `DM_QUANT_DEBUG=1` remains the one env var (debug-only, prints every LinearLike quant format); `CUBECL_AUTOTUNE_LEVEL` is the cubecl runtime's own knob, exposed as `--autotune`. Everything else is a typed flag: `--timers`, `--memlog`, `--quant-check`, `--log`, `--detach`, `--guard` (see `--help`).
- `--jepa-weight` / `--dspark-weight` / `--dspark-k` — auxiliary objectives on top of CE (`core/src/aux.rs`, ON by default at 0.05 / 0.1 / K=4): JEPA = data2vec-style masked latent prediction against an EMA teacher (burn-jepa; momentum 0.999, teacher advanced after every optimizer step) + KoLeo anti-collapse; DSpark = DeepSeek-style draft head correcting frozen logits into the next-K tokens (burn-dspark, used instead of MTP; gamma 4.0). Aux value is logged as `aux=` on log steps. Set both weights to 0 for the pure-CE baseline.

## GPU/CUDA quirks (hard-won, do not rediscover)

- **Never dynamically slice a 4D autodiff tensor**: cubecl on sm_120 crashes with `CUDA_ERROR_ILLEGAL_ADDRESS`. This is why L_Rec is accumulated inside `loop_block.forward_full_state` (per-step CE on `[b*t,d]` reshapes) instead of materializing `[N,b,t,d]` step hiddens and slicing them. Keep it that way.
- **bf16 logits NaN**: final norm + lm_head must run in fp32 even in BF16 mode (`model.rs` casts to F32 before the head). Loop-internal L_Rec logits likewise fp32.
- **cubecl memory pool is high-water**: reserves pages for every size ever seen, never frees → long runs OOM. `train_loop` calls `memory_cleanup()` periodically; `init_pools` (ExclusivePages) must run before the first allocation. Pool is NOT enabled by default.
- **burn-msa `gradient_detach` leaks autodiff nodes** (~74/step, OOM in long runs) on pre.3. Keep `gradient_detach = false` (index branch trains, tiny cost).
- `LinearLike` pads out_features to a multiple of 4 (cubek matmul vectorization, N%4==0) then slices back; keep the slice on all new heads.
- **Training instability on this box (pre-existing, open)**: NaN episodes appear in ANY config (fp32+adamw included, `--quant fp32 --opt adamw` 150-step-clean runs were lucky seeds) once the model overfits hard — with the 0.85 MB test corpus loss hits ~0.5 by step 50 and the KDA recurrence goes NaN (a_log overflow fixed with a clamp in burn-kda 2026-08-29; deeper overflow path not isolated — bisect showed `--no-kda` stays clean through deep overfit). Moonshot/FLA decay init (`a_log=-3`, `b_alpha=1.0`) + clamp measurably extended the clean window (110+ steps, Muon+, fp32, no NaN on 2026-08-29 vs 45-127 before). Fp8 quant (sm_120 default) additionally degrades at overfit (range overflow). This is an overfit-corpus artifact: on a real loss profile (3+) it should not trigger; verify on real data before chasing further. OOM flood follows NaN episodes (~10-50 steps later); `memory_cleanup` right after NaN makes it worse (pool goes bad), so NaN-skip does NOT call cleanup.
- **bf16 compute path on CUDA**: fixed 2026-08-29. The rule: mixed-dtype ops (bf16 activations x fp32 weights, bf16+f32 adds) NaN on this stack, so `--bf16` computes in fp32 and stores activations in bf16 — cast to fp32 before every Linear (controller, KDA, halt head, SpectralLinear inputs) and cast the residual/GR writes back to the activation dtype. Verified: 60 steps, 0 NaN, loss 5.53→2.21. Caveats: MSA/Engram kernels are f32-only (inputs cast), the KDA fused chunked kernel is f32-only (falls back to tensor ops), and bf16 runs are slower than fp32 (cast copies + tensor-path KDA) — revisit fused bf16 kernels for speed. Fp8 quant (sm_120 default) still degrades at overfit; `--quant fp32` is the stable combo. This is also why Muon+ NS stays off the [d,d] projections (fp32 NS on [768,768] costs ~40 s/step — tensor cores need the bf16 path).
- TSCT ortho: WIRED (2026-09-02, don't re-investigate). `LinearLike::retract(iters)` does a real polar retraction (burn-spectral, keeps autodiff tracking); `train_loop` calls `model.retract_tsct(cfg.retract_iters)` every step (default; `--retract-every`/`--retract-iters`), lm_head included. Covered by the `tsct_retract_restores_ortho` test.
- **max_ortho metric is per-entry** (Frobenius `||UᵀU−I||_F` / rank, fixed 2026-09-04 after GPU probe `ortho_probe`): the raw F-norm scales ~k and sits ABOVE the threshold from step 0 — the NS-3 retract's own convergence floor is ~4e-3 raw (~6e-5 per-entry at r=64), so the old unnormalized check fired the one-way fp32 fallback on EVERY fresh run and the factor-quant forward (Fp8 on sm_120) never actually engaged in any pre-fix run. Fresh init reads ~1.4e-4 per-entry; threshold 1e-3 per-entry = genuine drift. Masters are always fp32 params — `--quant` picks the forward path only, so checkpoints are format-agnostic and `--quant fp32` after a fallback run reproduces the old behavior exactly.

## Design playbook: what to adapt from Qwen3.8-Flash-Next (tech_report.pdf)

The report's architecture (125B MoE, 6B active, 51B n-gram params off-accelerator) is the closest published match to dormouse's goals. Adaptations ranked by payoff for a 16 GB GPU + 64 GB RAM box:

1. **RAM offload via host-prefetched n-gram tables (the big one)**. Qwen stores 51B n-gram embedding params in host memory: deterministic hash addressing → async prefetch of the next batch's rows (pinned memory, separate CUDA stream) overlapped with compute, so host RAM is a latency-free extension of VRAM. dormouse's Engram already uses deterministic FNV keys — scale the 3×4096 tables up (millions of slots, bf16 rows) and keep them in RAM, prefetch per-batch. Rule from the report: n-gram tables train with Adam, weight decay disabled. Loss drops monotonically with vocab scale; downstream saturates — evaluate both.
2. **Gated Residual (GR)**: widen the residual stream to 4 branches; read = elementwise sigmoid gate on a low-rank bottleneck (rank d/8) over group-RMSNorm'd branches; write = one scalar per branch; no branch-mixing operator Hres. Replaces ReZero scale and pre-norm. Report: −0.026 loss at 276B tokens, zero loss spikes at 4× LR, larger LR/batch become safe, no qk-clip/SwiGLU-clip needed (gates bound activations). Cheap: scalar writes, one low-rank read. FP8 residual state later halves traffic. Also `GatedNorm` (RMSNorm ⊙ σ(W2 SiLU(W1 RMSNorm(u)))) helps everywhere. Do NOT use sparse writes (top-2 branches): fine in pretraining, degrades post-training. **Wired as `use_gr` config flag (off by default for checkpoint compatibility; `crates/dormouse-core/src/gr.rs`, all slicing 2D/3D — a 4D gate tensor would crash sm_120), convergence-tested on NdArray.**
3. **Muon+ (burn-fused `burn-muon-plus`, arXiv 2602.21545)**: Muon + post-polar ColRow normalization, fused CUDA kernels, hybrid 2D→Muon+/1D→AdamW. **Wired into `dormouse-train` as the default optimizer** (`OPT=mix`, policy in `train/src/optim.rs`), with the report's param-group routing: Muon+ ColRow on 2D linear maps only (attn q/k/v/o, GDN projections, expert fc1/fc2, out_proj); AdamW for embeddings, output head, controller/router, low-rank projections (orthogonalization hurts them); n-gram tables on Adam with weight decay disabled. `ns_steps=8` (report's stability choice; Muon+ default is 5). `validate_routing` re-checks the policy against the live module tree at startup — a stale marker (module renamed) fails loudly instead of silently falling back to AdamW. Report deltas still open: split fused params (qkv per-head, SwiGLU gate/up halves) BEFORE orthogonalization — fusing mixes singular directions; capture the step in a CUDA graph (hundreds of small kernels after split). Skip the report's Polar Express schedule and γ = 0.2·max(A,B): Muon+ already ships its own validated recipe (quintic NS_COEFFS, Bernstein factor max(1, m/n)^0.5). Fallback-group alternative: Adan (arXiv 2208.06677) via `OPT=adan`/`OPT=mix-adan` (Nesterov + gradient-difference, ships in burn-optim). bf16 plan already targets Muon moments bf16 + stochastic rounding, MuonQ 4-bit.
4. **Sparse attention indexer (QSA → MSA)**: train the MSA block-indexer in two stages — (a) distill the dense attention distribution (max-pooled to blocks, KL) into the indexer at high LR for ~1k steps, (b) then joint sparse training. Indexer recipe: MQA (4 q-heads, 1 shared k-head), avg-pool keys into blocks r=4, block-causal ReLU scoring, top-KB blocks + always include the tail tokens of the final incomplete block, partial RoPE. Reuse top-k indices across MTP/speculative steps. At 1M ctx: 7.6× prefill / 4.9× decode vs dense.
5. **GDN details for KDA** (already the hybrid shape dormouse uses): sigmoid output gate (not SiLU), zero-centered RMSNorm everywhere, L2-normalized q/k, decay α_t = exp[−exp(A)·softplus(Wα x + bα)]. One full-attention layer per 4 (dormouse's per-iteration router blend covers this; keep RoPE in the attention arm — NoPE → endless generation after post-training). `use_short_conv` (report's local-bias choice) was tried and REVERTED: it made fp32+AdamW NaN at ~step 60 on this box while the same recipe ran 150+ steps clean without it (measured 2026-08-29) — trace inside burn-kda before re-enabling. KDA state dtype follows the inputs (bf16 under `BF16=1`, fp32 otherwise — Moonshot FlashKDA trains bf16 state); decay init matches the Moonshot/FLA recipe (`a_log=-3`, `b_alpha=1.0` — conservative alpha~0.08 at start). FlashKDA math (K3 decay, chunked WY, chunk 16) already matches burn-kda; their CUTLASS kernels are the remaining perf delta.
6. **Hyperparameters & stability**: with Muon+GR, batch-size warmup is wasted (−18.8% extra steps, no gain) — start at target batch/LR; optimal LR/batch shift up. Refit scaling laws per architecture change (report: new recipe ends 7.8e-3 better than old-recipe hyperparams at same budget). **Stress-test protocol** (cheap, do it on 16 GB): constant LR at 2× and 4× optimal, count loss spikes (> 201-step rolling median + 0.1), p99.9 pre-clip grad norm, per-block activation max. Stability = gate/bounded activations, not clipping.

## Design playbook: Energy-Based Models (research pass 2026-09-04)

Papers surveyed: **EBT** "Energy-Based Transformers are Scalable Learners and Thinkers" (arXiv:2507.02092 — energy head over (context, candidate) pairs, inference = energy minimization; 35% faster scaling w.r.t. data/depth/params/FLOPs, +29% more gain from inference compute than Transformer++; 44M AR EBT on RedPajama-32B beats Transformer++), **NRGPT** (arXiv:2512.16762, ICLR 2026 — GPT as an EBM: per-token energies, weight-shared recurrent refinement with per-head D×D J matrices, generation = exploration of the energy landscape that provably reduces to gradient descent; notably resistant to overfitting), **EDLM** (NVIDIA, ICLR 2025 — energy-corrected logits for diffusion LMs), **Residual EBM** (Meta — sequence-level EBM residual over a frozen base LM), **EBRM** (arXiv:2504.13134 — energy-based reward models, energy-guided reward refinement), **EB-JEPA** (arXiv:2602.03604 — JEPA *is* an EBM in LeCun's framing: energy = embedding-space prediction error).

dormouse's LoopBlock is already structurally an EBT (weight-shared recurrent refinement + adaptive depth); what's missing is the explicit energy readout. Ranked applicability:

1. **Energy head on the loop state (EBT-style, the direct fit)**: scalar head E(h_k, e_v) scoring the loop state against candidate token embeddings, trained InfoNCE-style — target byte vs negatives sampled from lm_head softmax or uniform. No MCMC anywhere: the candidate set is the 256 bytes, enumerable — this is just a contrastive head, same machinery as the existing DSpark aux. Gains: calibration/OOD signal, a principled inference-time compute knob (more iterations on hard contexts), a possible regularizer for the overfit-NaN episodes (NRGPT reports overfit resistance). Cost: one small head + 256 scores per position per iteration. Implement as an `aux.rs`-style aux objective first, weight 0 default, A/B against pure CE.
2. **Energy-based halting**: PonderNet's λ_k is a learned proxy for "the loop stopped improving". The EBM version: halt when ΔE between iterations plateaus. Cheap first step — log ΔE per iteration and check it correlates with the learned λ_k; only then A/B as an actual halt criterion.
3. **Post-training EBM reranker (EBRM / Residual-EBM)**: in POST_TRAINING.md's self-evolve loop, K=8 noisy rollouts are currently picked by the PonderNet Q-head — an EBM scorer (segment- or sequence-level) is a drop-in upgrade for best-of-n selection, and EBRM-style energy refinement applies to RLVR rewards. Zero changes to the base model; train the scorer on verifier labels.
4. **Do NOT adopt**: MCMC/CD training (Langevin/HMC over byte sequences — slow and unstable on this stack), NRGPT's full re-architecture (per-head D×D J matrices are VRAM-infeasible at dormouse scale and ~double inference FLOPs — anti-goal), diffusion-EBM (dormouse is AR). EDLM's energy logit correction only matters for diffusion, but its "energy as verifier" reading is what item 3 uses.

## State notes

- Current API (don't revert): `forward_with_hidden(input_ids, hashed_ids, host_rows, targets, teacher)` → `(logits, rec, p_dist, kda, aux)`. L_Rec is accumulated inside the loop (never materialize `[N,b,t,d]`); `targets` are byte indices `[b,t]` Int, and the per-iteration CE gathers the target log-prob (`log_softmax.gather`) — there is no one-hot `[b*t,v]` tensor anymore (2026-09-04). `loss(rec, p_dist)` = L_Rec + β·KL. `host_rows` `[b,t,96]` f32 drives the RAM-offload Engram; `teacher` is the EMA copy for JEPA. `examples/quant_probe.rs` is up to date with this API.
- Perf state (2026-09-04): host-table CPU-Adam runs every step (`--host-adam-every`, was accidentally gated on log steps = 1/100 of updates); L_Rec CE gathers the target log-prob (no one-hot `[b*t,v]`); aux/loss scalar clones only happen on sync steps; the device syncs only on steps that read something back (log cadence, host-Adam cadence, timers); `save_ckpt` streams through a 1 MB BufWriter (2× (model+optim) RAM transient — burnpack can't stream records, that's the floor). A/B old-vs-new CE at small/batch6/s512: no wall-clock delta (~9.7 s/step, launch-bound) — the win is removed temporaries/pool pressure, visible at larger scale. Launch: `--data <corpus dir> --eval <held-out> --eval-every 500 --preset small --batch 10 --seq-len 512 --engram-ram --engram-slots 48000000 --host-adam-every 1 --guard --detach --log <file>`; factor quant defaults to Fp8 on sm_120 and now actually stays on (pre-fix runs silently ran the fp32 forward) — first post-fix runs are also the first real Fp8 A/B, `--quant fp32` is the rollback.
- 5060 Ti budget rules of thumb (from bf16_KERNEL_PLAN.md): 1B model bf16 ≈ 2 GB weights, +2 GB per batch-16 s1024 step. The remaining headroom is where the RAM-offload playbook above buys scale.
