01what it is

A small model you can check

dormouse is a byte-level language model: it reads text as 256 possible bytes instead of tokens. That makes the whole thing inspectable — the input is the file itself, and every number on this page can be recomputed from the logs in the repository.

256
input symbols
No tokenizer and no vocabulary to train. The model sees the text as it is, down to the byte.
95M
parameters
Twelve transformer layers — small enough for one 16 GB card, large enough to say something.
1
GPU, the whole stack
No cluster and no rented hours. One workstation, one card, and a public log for every run.

02why it exists

A number you cannot check is a rumour

Most claims about models are unverifiable from the outside. This project is built the other way around: every claim names its measurement, every failed idea stays published, and a claim that cannot be reproduced is retracted in public.

rule 01
Measure, then claim
A mechanism ships only if it beats its own removal on held-out data. A faster one that costs quality is marked rejected and never drives a headline.
rule 02
Keep the failures
A retraction is published next to what replaced it. Deleting it would be the one dishonest move available.
rule 03
One machine
If a result needs a cluster to reproduce, it is not evidence. Everything here is meant to run on a workstation like yours.

08retractions

  
What we got wrong

  
Every entry was published here first, then measured wrong. Deleting them would be the one
    dishonest move available, so they stay next to what replaced them.

  
    
    
  • “16× from the recipe ladder”
    
      
    1.92× from the optimizer rung, measured
    
      
    The 16× was Ripple-65B's result at 4B parameters, not ours.
    • 
    
  • “3 Newton–Schulz steps are a tie”
    
      
    +0.27 BPB at [832, 3072]
    
      
    The published non-monotone result, and this repo's own “1.17e-15 from the manifold”,
        were both measured on rank-64 factors. On the dense stack the 3-step chain does not converge.
    • 
    
  • “209× less compute than GPT-2”
    
      
    53×, and only per byte
    
      
    The first figure counted GPT-2's 40 GB as 40 G positions; at ~4 bytes per BPE token
        it is 10 G.
    • 
    
  • “1.927 BPB at 98 MB”
    
      
    1.660 BPB at the same bytes
    
      
    Captured before the Muon learning-rate fix (a scheduler overwrote the group's LR
        every step).
    • 
    
  • “34 MB of state at 1M”
    
      
    33 MiB per CSA slot — 99 MiB for the 3-slot loop
    
      
    The figure was ONE CSA ring read as the total. The loop carries
        (kda_state, csa_state) per iteration slot, and a 12-layer stack would be
        396 MiB. A 1M forward has still not been run.
    • 
    
  • “1M context, in the measurements row”
    
      
    designed, not measured
    
      
    The stat card sat under “each one a measurement”. The state arithmetic is exact;
        the capability is untested, and the training that would test it (a CSA model at 8K) is queued, not run.
