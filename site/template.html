A language model small enough to understand.

dormouse learns to read and write text one byte at a time, on a single 16 GB graphics card. This page walks through what it is, the ideas inside it, and what it can do.

01 · the input

It reads the file itself

Most language models begin by chopping text into tokens — chunks of words picked from a fixed dictionary. dormouse skips that step entirely.

Its alphabet is the 256 values a byte can hold, so the input is the file exactly as it sits on disk: spaces, punctuation, emoji, code, everything. Nothing is lost in a translation to token ids, and the model can never meet a word it has no symbol for.

The rain beside this text is that alphabet: the same bytes a computer reads, drawn as their binary shadow.

02 · the model

Twelve layers, one direction

The model is a plain stack of twelve transformer blocks — the same shape that powers most language models today, cut down to fit one card. A byte goes in, twelve blocks later a prediction comes out.

No mixture of experts, no recurrence, no clever detours. A deliberately simple shape, so that every experiment changes exactly one thing and the result means something.

03 · the optimizer

Muon thinks in matrices

Networks learn by nudging millions of numbers downhill. The usual tool is Adam, which treats every number on its own. Muon treats a weight matrix as a matrix.

Before each step it orthogonalizes the update — every direction gets the same strength — which keeps the step well-conditioned and lets large matrices learn faster. We run Muon for the big matrices and Adam for the small ones.

Moving the matrix chain from fp32 to bf16 made every step 1.92× faster, for 0.01 bits per byte — inside the measurement noise.

04 · the machine

One graphics card, on purpose

Everything trains on a single RTX 5070 Ti with 16 GB of memory. That is the constraint the project is built around: a result that needs a cluster is hard to check, and a result you cannot check is hard to trust.

The whole run — data, model, optimizer, evaluation — fits on a workstation you could buy for the price of a laptop.

06 · the inside

What the model sees

Every byte is a small bet. Before it reads a character the model has a distribution over all 256 possibilities; after it sees the character, the surprise is −log2 p.

The strip below is a real 1024-byte window the model never trained on. Taller marks are places it hesitated; flat stretches are text it could almost guess.

Reading a model's confidence byte by byte is how you find out what it has actually learned — and where it is bluffing.
