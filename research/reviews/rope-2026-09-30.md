## The answer, in one line

**FLA's official KDA has no RoPE at all — the layer is NoPE, positionally.** RoPE
in a KDA model comes from the *other* layers of the hybrid, and our arm is a
**cross-family transplant**, exactly as the Qwen3.8 playbook predicted.

## 1. Does the official KDA use RoPE? No. Zero occurrences.

`fla/layers/kda.py` (316 lines, the whole file) contains **no** occurrence of
`rotary` or `rope`. The class is `KimiDeltaAttention` (`fla/layers/kda.py:28`),
and its forward is, in order:

| line | what |

| `fla/layers/kda.py:248` | `q = F.silu(self.q_proj(hidden_states))` |
| `fla/layers/kda.py:249` | `k = F.silu(self.k_proj(hidden_states))` |

| `fla/layers/kda.py:272`, `:292` | `use_qk_l2norm_in_kernel=True` (chunk and fused_recurrent arms) |

No `self.rotary` is ever constructed — contrast the layers in the same repo that
do have one: `fla/layers/abc.py:141-142` (`if self.use_rope: self.rotary =
RotaryEmbedding(self.head_k_dim)`), `fla/layers/attn.py:83`,

## 2. Where the L2 norm lives — and this is the part that matters for placement

The q/k L2 normalization **is not in the layer and not in the naive reference**;
it is a kernel-side step:

- `fla/ops/kda/chunk.py:56-60` — `# Apply l2norm` / `if use_qk_l2norm_in_kernel:
  q, q_rstd = l2norm_fwd(q); k, k_rstd = l2norm_fwd(k)`. The backward is
  `chunk.py:184-186` (`l2norm_bwd`), so the rotation we add lands *before* this
  point in the dataflow — inside the kernel we are reimplementing.
- `fla/ops/kda/naive.py` has **no** l2norm at all. The pure-PyTorch references
  our existing fixture compares against take `q`/`k` exactly as the layer hands
  them over. Consequence for the oracle: our forward normalizes *outside*, so
  a rope variant must apply the rotation in the same relative position —
  **rope before our L2 norm** — or the fixture is comparing two different
  functions and the red would mean nothing.
- FLA's `use_qk_l2norm_in_kernel` defaults to **`False`**
  (`fla/ops/kda/chunk.py:40`, `fla/ops/kda/fused_recurrent.py:253`) and the
  layer turns it on. So the norm is KDA-specific and optional, not part of the
  recurrence's algebra.

## 3. The placement question — rope before or after the L2 norm

**Our constraint, stated first:** q/k are L2-normalized (K3 stability choice,
AGENTS.md §3.5 item 5: "L2-normalized q/k"). RoPE is a block-diagonal rotation
whose 2×2 blocks are `[[cos, -sin], [sin, cos]]`, so it preserves the L2 norm
*exactly*.

**Therefore, at full-head rotation, the two placements are the same function:**

```
l2norm(rope(x)) = rope(x)/‖rope(x)‖ = rope(x)/‖x‖ = rope(l2norm(x))
```

This is arithmetic, not a citation, and it is pinned by a test in this lane
(`rope_commutes_with_l2norm_at_full_fraction`). It is the answer to the
question as asked: **for a full-head rope the placement is free, and no source
can be said to "prefer" one.**

**Where the placement stops being free: a partial rotation.** FLA's own
reference supports one — `rotary_embedding_ref` (`fla/modules/rotary.py:30-36`):

```python
ro_dim = cos.shape[-1] * 2
assert ro_dim <= x.shape[-1]
...
return torch.cat([x[..., :ro_dim] * cos + rotate_half(x[..., :ro_dim], interleaved) * sin, x[..., ro_dim:]], -1)
```

The un-rotated tail `x[..., ro_dim:]` is carried through untouched, and once the
L2 norm is over *all* head dims it mixes rotated and unrotated coordinates — so
`l2norm(rope_partial(x)) ≠ rope_partial(l2norm(x))`. FLA treats that fraction as
an explicit knob and keeps the rotation *before* the scan:
`fla/layers/mamba3.py:60` ("**blockwise rotary on Q/K before the SSM scan**"),
`fla/layers/mamba3.py:71` (`rope_fraction: float = 0.5`),
`fla/layers/mamba3.py:129-130` (refuses anything but 0.5 or 1.0).

**The one upstream site that has both a rope and a per-head norm on the same
q/k** is the ABC layer family, and it applies the rope to the **raw,
un-normalized** q/k: `fla/layers/abc.py:202` (head rearrange) →
`fla/layers/abc.py:204` (`if self.use_rope:`) → `fla/layers/abc.py:208`
(`q, k = self.rotary(q, k, seqlen_offset=seqlen_offset)`). `use_rope` defaults
to **`True`** there (`fla/layers/abc.py:43`). ABC attention has no
`use_qk_l2norm_in_kernel` flag, so this is not literally a rope-vs-norm
ordering — but it is upstream's convention: **rotate first, normalize never
(because the norm is the kernel's), and let the kernel normalize after.**

**Our choice: rope before the L2 norm, at fraction 1.0.** It matches the
"before the scan" convention (`mamba3.py:60`) and the ABC placement
(`abc.py:202-208`), and at fraction 1.0 it is provably the same function as the
other order — so the choice costs nothing and the equivalence is a test rather
than a belief. Fraction is not wired; a future partial rope must re-derive the
order rather than inherit it.

## 4. What Kimi Linear's hybrid does instead — the transplant, cited

FLA ships the hybrid machinery, and it is the answer to "where does position
come from in a KDA model":

- `fla/models/hybrid.py:17-23` — `HybridAttentionSpec`:
  *"JSON-serializable settings for **standard attention at selected model
  layers**"*, with `rope_theta: float` as one of the fields (`:23`), defaulted
  and validated at `:103-115` (`10000.`).
- `fla/models/hybrid.py:190-200` — `get_hybrid_attention_spec`'s docstring:
  *"Unassigned layers return `None` and **retain their model's native mixer**."*
  That is the NoPE statement for the KDA half of a hybrid, in upstream's own
  words.
- The layers that *are* assigned get their rope from the standard-attention
  layer: `fla/layers/attn.py:83` — `self.rotary = RotaryEmbedding(dim=self.head_dim,
  base=self.rope_theta)`, applied at `fla/layers/attn.py:125`
  (`q, k = self.rotary(q, k, seqlen_offset=seqlen_offset, max_seqlen=..., cu_seqlens=...)`).
  Note it is applied to the raw q/k, before the optional `qk_norm`
  (`fla/layers/attn.py:51-53`, an RMSNorm, off by default) — upstream's habit
  again: **rotate, then normalize.**

So: **KDA layers NoPE, interleaved full-attention layers RoPE, `rope_theta`
10000.** The transplant into a pure-KDA loop is the interesting move, and it is
required regardless of pretrain parity: AGENTS.md §3.5 item 5 records the
playbook finding as "NoPE → endless generation after post-training", and the
owner's goal is the full SFT→RLVR→distill loop (`POST_TRAINING.md`). A model
that cannot be steered after pretraining is not a candidate for that pipeline
whatever it scores at step 2000. **This is the justification, and it is a
cross-family transplant, not a Kimi Linear reproduction.**

## 5. RoPE is parameter-free — from the source, not from our arithmetic

`RotaryEmbedding` holds `inv_freq` and `scale` as **non-persistent buffers**:
`fla/modules/rotary.py:379` (`self.register_buffer("inv_freq", ...,
persistent=False)`) and `:384` (same for `scale`). The frequency formula is
`fla/modules/rotary.py:410-414` — `1.0 / base ** (arange(0, dim, 2) / dim)`,
`base = rope_theta`. **Zero `nn.Parameter`, zero persistent state**, so:

- the arm adds **no parameters** and changes no param count;
- **no checkpoint format change** (nothing to save, nothing to version);
- nothing to load in an old checkpoint, nothing that breaks one.

That is a property of the mechanism, stated so a reader does not have to take
our word for it: rotary carries no weights because the rotation is a function of
position, not a learned parameter.

### Two bugs this lane's own tests had, and what they are worth

Both were found by the gate, not by reading, and both are the same defect class
as `kda_oracle.rs`'s lesson that a self-comparison cannot see a choice:

1. **Two builds of one config are not the same model.** Both module tests were
   red at first because `KdaModule::new` draws every projection from the device
   RNG and `Device::seed()` does not rewind a consumed stream (AGENTS.md §3.7,
   the `two_models_one_seed_are_bit_identical` withdrawal). The fix is
   `try_load_record`, not a seed.
2. **A permuted tensor's `into_data()` is in the permuted order.** `project`
   returns `[B, H, T, D]` and `apply_rope` takes `[B, T, H*HD]`, so comparing a
   projection's flat data against `apply_rope`'s input silently reads the head
   axis as the time axis. This bit the rotation comparison once and the module
   identity once.
