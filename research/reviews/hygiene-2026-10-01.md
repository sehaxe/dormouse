## 2. burn-fused README falsities fixed

`vendor/burn-fused` is 20 crates (was 28; eight deleted 2026-09-28, fate table
`docs/library-crate-fate.md`), MIT, and gated by
`.github/workflows/fused-library.yml` at the dormouse root. It has **no
`.github/` of its own in this copy** — the fork's own `ci.yml` was never
inherited here and the ten per-crate ones were deleted (`4963c3a`).

Top five, all in `vendor/burn-fused/README.md` (`ead9f38`), in the direction that
makes a reader trust something unchecked:

1. **"the committed CI baselines ... re-checked on every PR, fails on >20%

   `benches/` is `--exclude`d from the two jobs that could. Measured: no bench
   job exists in the file. `bench/baselines.json` has 10 entries and one of them,
   `msa_sparse.fused_ms`, is for a crate deleted 2026-09-27.
2. **"10 of these 20 are in dormouse's build, the other 10 are reference ports
   nobody links."** Measured off the `path =` edges in `crates/*/Cargo.toml`:
   **13 in build, 7 not.** It was 10/10 on 2026-09-28; `burn-attnres` (wired
   2026-09-30) and `burn-situ` (2026-10-01) moved since. Not in build:
   `burn-eggroll`, `burn-es`, `burn-parcae`, `burn-ptrn`, `burn-rope`,
   `burn-sct`, `burn-swiglu`.
3. **A checked roadmap item against `burn-msa`'s `sparse_kernel.rs`** — a file
   that does not exist. The whole roadmap went with it: an unchecked box in a
   README is a wish.
4. **"100+ technologies in sight"** over 20 crates, in the file whose job is to
   say what exists.
5. **The implied CI gate.** The README now opens by saying this directory is a
   vendored copy, the gate is the root workflow, there is deliberately no
   `cuda-tests` job, and the GPU check is `tools/gpu-gate.sh`.

Added, because they were missing and true: the 20-crate table with each
manifest's own `description`, `cuda`/`autodiff`/in-build columns; the
single-crate commands (`cargo test -p burn-gdn2`, `tools/gpu-gate.sh`,

## 6. Flagged, not touched

- **`vendor/{cubecl-fix,cubek-fix}/*/Cargo.toml.orig`, 5 files, 12 KB.** `patch`
  backups from the vendoring, tracked since `d1a76fe`. Mechanically junk, but
  they are the only pre-patch copy of those manifests in the tree — the fork was
  committed already-patched, so git history has no "before". The task's rule is
  that ambiguous goes in the report, not the `rm`, and whether we want to
  re-derive the upstream delta later is not a hygiene call. **Owner's call.**
  Reproduce the check: `git ls-files 'vendor/**/*.orig'`.
- **`burn-fused/Cargo.toml:7` — the facade's `description` still says "100+
  technologies"**, same claim as the README's. A manifest, not a README, and it
  is published crates.io metadata; the README fix does not reach it.
- **`docs/library-crate-fate.md` is titled "The 28 crates"** and says "Ten of its
  28 crates are compiled into a training run". Both were true at its snapshot
  `422414c` (2026-09-28) and the doc names the snapshot in line 3, so it is a
  dated record rather than a false statement — but the "ten" is now 13, and it
  is the document the new README points a reader at. Root `docs/`, not the
  vendor library.
- **The 6 tracked `*.bin` oracle fixtures** (19 MB, `burn-gdn2/tests/`) are
  matched by `*.bin` in the root `.gitignore` and un-ignored in
  `vendor/burn-fused/.gitignore`. Correct as it stands, and that file documents
  the trap (`git check-ignore -v` before trusting a green run) after a 1000-case
  fixture went missing for exactly this reason on 2026-09-29. No change; the
  root rule is what makes the footgun possible for anything added later.
- **The `crates.io` badges** in ~13 per-crate READMEs render for crates that may
  never have been published (the library is consumed by `path =`). Whether they
  resolve needs a network check, which is out of a text-only lane.
- **`bench/baselines.json` still holds `msa_sparse.fused_ms`** and covers 10 of 20
  crates. Deleting a measurement is not the same as deleting the fact that it was
  taken, and `benches/src/main.rs` may still emit the key — that is a code
  question, so the two labels in §2/§4 point at it instead.

## Reproduce

```bash
git ls-files | grep -iE '\.log$|\.tmp$|\.bak$|\.rej$|\.orig$|desktop\.ini|\.DS_Store'
cd vendor/burn-fused && grep -rn '\b28\b' --include=*.md . | grep -v target
cd vendor/burn-fused/crates && grep -rn 'actions/workflows/ci.yml' */README.md
python3 - <<'PY'
import re,glob,os
used={m.group(1) for t in glob.glob('../../crates/*/Cargo.toml')
        for m in re.finditer(r'^\s*(burn-[\w-]+)\s*=\s*\{[^}]*path\s*=\s*"[^"]*burn-fused',open(t).read(),re.M)}
print(len(used),"in build:",sorted(used))
PY
```
